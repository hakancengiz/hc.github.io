JWT Authentication Nedir? Token Üretme ve Doğrulama

token·4 Mayıs 2026·~5 dk okuma

Modern web uygulamalarında en sık kullanılan kimlik doğrulama yöntemlerinden biri JWT (JSON Web Token) yapısıdır.

JWT’yi sadece “login olunca verilen bir token” gibi düşünmek eksik olur. Asıl mesele şu:

Sunucu, kullanıcıyı her istekte tekrar tekrar kontrol etmek zorunda kalmadan güveni nasıl sürdürüyor?

JWT burada devreye girer.

JWT Nedir?

JWT, açılımıyla JSON Web Token, iki taraf arasında güvenli bilgi taşıyan bir token formatıdır.

Basitçe:

  • Kullanıcı giriş yapar
  • Sunucu bir token üretir
  • Kullanıcı bu token ile tüm isteklerini yapar
  • Sunucu her istekte tekrar login sormaz

JWT’nin Yapısı

JWT üç parçadan oluşur:

  • Header (başlık)
  • Payload (içerik)
  • Signature (imza)

Bu üç yapı nokta (.) ile ayrılır:

xxxxx.yyyyy.zzzzz

1. Header (Başlık)

Token’ın tipini ve kullanılan algoritmayı içerir.

Örneğin:

{
  "alg": "HS256",
  "typ": "JWT"
}
  • alg → algoritma (örnek: HMAC SHA256)
  • typ → token tipi

2. Payload (Veri kısmı)

Kullanıcıya ait bilgiler burada taşınır.

Örnek:

{
  "userId": 1,
  "email": "test@test.com",
  "role": "Admin"
}

Buradaki kritik nokta:

Payload şifreli değildir, sadece imzalanmıştır.

Yani okunabilir ama değiştirilemez.

3. Signature (İmza)

Token’ın değiştirilmediğini garanti eder.

Sunucu şu şekilde üretir:

HMACSHA256(
  base64(header) + "." + base64(payload),
  secretKey
)

Buradaki secretKey, sadece sunucuda bilinen gizli anahtardır.

JWT nasıl çalışır? (Akış)

  • Kullanıcı login olur
  • Sunucu kullanıcıyı doğrular
  • JWT oluşturur
  • Client’a gönderir
  • Client her istekte bu token’ı gönderir
  • Sunucu token’ı doğrular

ASP.NET Core ile JWT Üretimi

Şimdi gerçek bir örnek yapalım.

1. Gerekli paket

dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer

2. Token üretme servisi

using System; // Temel sistem fonksiyonları için eklenir
using System.IdentityModel.Tokens.Jwt; // JWT oluşturmak için kullanılır
using System.Security.Claims; // Kullanıcı bilgilerini taşımak için kullanılır
using System.Text; // Encoding işlemleri için kullanılır
using Microsoft.IdentityModel.Tokens; // Güvenlik anahtarı işlemleri için kullanılır

public class JwtService // JWT işlemlerini yöneten servis sınıfı
{
    private readonly string _key = "super_secret_key_123"; // Token imzalamak için gizli anahtar

    public string GenerateToken(string userId, string email) // Token üretme metodu
    {
        var claims = new[] // Token içine eklenecek bilgiler
        {
            new Claim("userId", userId), // Kullanıcı ID bilgisi eklenir
            new Claim("email", email) // Kullanıcı email bilgisi eklenir
        };

        var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_key)); // Gizli anahtar byte dizisine çevrilir

        var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256); // İmza algoritması belirlenir

        var token = new JwtSecurityToken( // JWT token oluşturulur
            issuer: "myapi", // Token’ı üreten sistem
            audience: "myapiUsers", // Token’ın geçerli olduğu hedef
            claims: claims, // Kullanıcı bilgileri eklenir
            expires: DateTime.Now.AddHours(1), // Token süresi belirlenir
            signingCredentials: creds // İmza bilgisi eklenir
        );

        return new JwtSecurityTokenHandler().WriteToken(token); // Token string olarak döndürülür
    }
}

3. Token doğrulama (Middleware ayarı)

ASP.NET Core’da doğrulama otomatik yapılır.

using Microsoft.AspNetCore.Authentication.JwtBearer; // JWT authentication için gerekli
using Microsoft.IdentityModel.Tokens; // Token doğrulama için gerekli
using System.Text; // Encoding işlemleri için gerekli

var builder = WebApplication.CreateBuilder(args); // Uygulama başlatılır

var key = "super_secret_key_123"; // Aynı secret key kullanılmalı

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme) // Authentication eklenir
    .AddJwtBearer(options => // JWT ayarları yapılır
    {
        options.TokenValidationParameters = new TokenValidationParameters // Doğrulama kuralları
        {
            ValidateIssuer = true, // Issuer kontrol edilir
            ValidateAudience = true, // Audience kontrol edilir
            ValidateLifetime = true, // Token süresi kontrol edilir
            ValidateIssuerSigningKey = true, // İmza doğrulanır

            ValidIssuer = "myapi", // Geçerli issuer
            ValidAudience = "myapiUsers", // Geçerli audience

            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(key)) // İmza anahtarı
        };
    });

var app = builder.Build(); // Uygulama oluşturulur

app.UseAuthentication(); // Authentication middleware aktif edilir
app.UseAuthorization(); // Authorization aktif edilir

app.MapGet("/secure", () => "Giriş başarılı!"); // Korunan endpoint

app.Run(); // Uygulama çalıştırılır

JWT neden bu kadar kullanılıyor?

Çünkü:

  • Stateless çalışır (sunucu session tutmaz)
  • Ölçeklenebilir
  • Microservice mimarisine uygundur
  • Performanslıdır

Kritik bir gerçek var. JWT güvenli değildir demek yanlış olur ama yanlış kullanılırsa ciddi risk oluşturur.

En sık yapılan hatalar

  • Secret key’i zayıf tutmak
  • Token süresini çok uzun yapmak
  • Payload içine hassas veri koymak
  • HTTPS kullanmamak
  • Refresh token mekanizması kurmamak

JWT’nin Yanlış Kullanımı (En Kritik Kısım)

JWT güçlü bir yapı olsa da yanlış kullanıldığında ciddi güvenlik ve mimari problemler yaratabilir.

1. Payload içine hassas veri koymak

JWT payload kısmı şifreli değildir, sadece imzalanır.

Yani herkes decode edip içeriği okuyabilir.

Yanlış kullanım örneği:

{
  "userId": 1,
  "email": "test@test.com",
  "password": "123456"
}

Burada ciddi bir hata var:

  • Password gibi hassas veri asla JWT içinde tutulmaz
  • Çünkü token ele geçirildiğinde herkes okuyabilir

2. Secret key’i zayıf tutmak

JWT güvenliği imzaya dayanır.

Eğer secret key zayıfsa:

  • Token sahteciliği yapılabilir
  • Başka kullanıcı adına token üretilebilir

Örnek kötü kullanım:

string secretKey = "1234"; // çok zayıf ve tahmin edilebilir

Bu, sistemi neredeyse açık hale getirir.

3. Token süresini çok uzun yapmak

Token süresi çok uzunsa:

  • Ele geçirilen token uzun süre kullanılabilir
  • Logout mekanizması etkisiz hale gelir

Yanlış örnek:

expires: DateTime.Now.AddYears(10) // aşırı uzun süre

Bu pratikte güvenlik açığıdır.

4. JWT’yi session yerine kullanmaya çalışmak

JWT stateless bir yapıdır.

Ama bazı projelerde şu hata yapılır:

  • Kullanıcı logout olur
  • Ama token hala geçerlidir
  • Sistem bunu “aktif session” gibi düşünmeye çalışır

JWT tek başına session yönetimi değildir.

5. HTTPS kullanmamak

JWT ağ üzerinden taşındığı için:

  • HTTP kullanılırsa token düz metin olarak yakalanabilir
  • Man-in-the-middle saldırılarına açık hale gelir

Bu yüzden JWT HTTPS olmadan asla kullanılmamalıdır.

JWT’nin en tehlikeli yanı şudur:

Sistem güvenli sanılır, ama aslında güvenlik tamamen geliştiricinin doğru kullanımına bağlıdır.

Yani JWT:

  • doğru kullanılırsa güçlüdür
  • yanlış kullanılırsa sahte kimlik üretmeye kadar gider

JWT’nin en önemli olayı şudur:

Sunucu seni hatırlamak zorunda değildir.

Kim olduğunu, neye yetkin olduğunu token söyler.

Yani kimlik doğrulama artık “sunucu hafızası” değil,
imzalanmış bir veri parçası üzerinden yapılır.

Sonuç

JWT:

  • Login sonrası kimlik taşır
  • Sunucu yükünü azaltır
  • Dağıtık sistemlere uygundur
  • Ama doğru kullanılmazsa güvenlik açığı oluşturur
