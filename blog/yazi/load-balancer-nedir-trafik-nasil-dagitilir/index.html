Load Balancer Nedir? Trafik Nasıl Dağıtılır?

servers·29 Nisan 2026·~5 dk okuma

Bir uygulama ilk başta tek sunucuda çalışır.
Her şey basittir. Tüm istekler tek bir yere gelir, işlenir ve cevap döner.

Ama kullanıcı sayısı arttığında işler değişir.

  • Sunucu yavaşlar
  • CPU dolar
  • RAM yetmez
  • İstekler gecikir
  • Kullanıcı bekler

İşte tam bu noktada kritik bir soru ortaya çıkar:

“Tüm kullanıcılar neden tek bir sunucuya gelsin?”

Cevap: Gelmemeli.

Burada devreye load balancer, yani yük dengeleyici girer.

Load Balancer Nedir?

Load balancer, gelen istekleri birden fazla sunucuya dağıtan sistemdir.

Türkçesiyle:
 Yükü paylaşır.

Yani kullanıcıdan gelen trafik tek bir sunucuya gitmez.
Birden fazla sunucu arasında paylaştırılır.

Bu sayede:

  • Sistem daha hızlı olur
  • Tek sunucu çökse bile sistem ayakta kalır
  • Daha fazla kullanıcıya hizmet verilir

Basit mantık

Düşün:

3 tane sunucun var:

  • Server A
  • Server B
  • Server C

Kullanıcıdan gelen 3 istek:

  • İstek 1 → A
  • İstek 2 → B
  • İstek 3 → C

Bu dağıtımı yapan şey load balancer’dır. Kullanıcı aslında tek bir sisteme bağlandığını sanır ama arkada birden fazla makine çalışıyordur.

Neden gereklidir?

Çünkü tek sunucu ölçeklenemez.

“Ölçeklenmek” demek, artan yükü kaldırabilmek demektir.

Bir noktadan sonra tek makineyi büyütmek (daha fazla CPU, daha fazla RAM) yeterli olmaz.

Bu yüzden yatay büyüme yapılır.

Buradaki yatay büyüme (horizontal scaling), yeni sunucular eklemek demektir.

Load balancer olmadan bu sunucuları yönetmek mümkün değildir.

Load balancer neyi çözer?

1. Performans

Trafik bölünür → her sunucu daha az yük alır → sistem hızlanır.

2. Yüksek erişilebilirlik

Bir sunucu çökerse diğerleri çalışmaya devam eder.

Buna high availability (yüksek erişilebilirlik) denir.

3. Ölçeklenebilirlik

Yeni sunucu eklediğinde load balancer otomatik olarak trafiği ona da dağıtır.

4. Tek giriş noktası

Tüm kullanıcılar tek bir IP ya da domain’e bağlanır. Arkada kaç sunucu olduğu kullanıcıyı ilgilendirmez.

Trafik nasıl dağıtılır?

Load balancer “rastgele” dağıtım yapmaz. Belirli algoritmalar kullanır.

1. Round Robin

En basit yöntemdir.

İstekler sırayla dağıtılır:

  1. istek → A
  2. istek → B
  3. istek → C
  4. istek → tekrar A

Basit ama etkili.

2. Least Connections

En az aktif isteği olan sunucuya gönderir.

Yani en boş sunucuya iş verilir.

Bu, daha dengeli sonuç verir.

3. IP Hash

Kullanıcının IP’sine göre hep aynı sunucuya yönlendirir.

Bu özellikle şu durumda önemli:

  • Kullanıcı oturumu (session) varsa

Yani kullanıcı her istekte aynı sunucuya gitmelidir.

4. Weighted Distribution

Sunucuların gücüne göre dağıtım yapılır.

Örneğin:

  • Güçlü sunucu → daha fazla trafik
  • Zayıf sunucu → daha az trafik

Layer 4 vs Layer 7 Load Balancer

Bu biraz teknik ama önemli.

Layer 4 (Transport Layer)

  • IP ve port üzerinden çalışır
  • Daha hızlıdır
  • Daha basittir

Layer 7 (Application Layer)

  • HTTP seviyesinde çalışır
  • URL, header gibi bilgilere bakabilir
  • Daha akıllıdır

Örneğin:

  • /api → backend sunucularına
  • /images → farklı sunuculara

Bu yönlendirmeyi Layer 7 yapar.

Gerçek hayattan örnek

Bir e-ticaret sitesini düşün.

Kampanya günü.

10.000 kişi aynı anda giriyor.

Eğer load balancer yoksa:

  • Tüm trafik tek sunucuya gider
  • Sistem çöker

Ama load balancer varsa:

  • Trafik 10 sunucuya bölünür
  • Sistem ayakta kalır

Kullanıcı hiçbir şey anlamaz.
Ama sistem mimarisi onu kurtarmıştır.

Sticky Session nedir?

Buna session affinity de denir.

Türkçesiyle:
 “Kullanıcıyı aynı sunucuya bağlı tutmak”

Bazı uygulamalarda kullanıcı bilgisi sunucu içinde tutulur.

Bu durumda kullanıcı her istekte aynı sunucuya gitmelidir.

Load balancer bunu sağlar.

Ama modern sistemlerde bu yaklaşım pek önerilmez.

Neden?

Çünkü:

  • Ölçeklenebilirliği zorlaştırır
  • Cache ve dağıtık yapı tercih edilir

Load balancer tek başına yeterli mi?

Hayır.

Bu çok kritik.

Load balancer sadece dağıtır.
 Ama sistemin geri kalanı da doğru tasarlanmalıdır.

Örneğin:

  • Stateless servisler (durumsuz servisler)
  • Merkezi cache
  • Dağıtık veri yönetimi

“Stateless” demek:
Sunucu, kullanıcıya özel bilgi tutmaz demektir.

Bu sayede her sunucu her isteği işleyebilir.

Basit C# simülasyonu

Gerçek load balancer donanımsal ya da özel yazılımdır.
Ama mantığı göstermek için basit bir simülasyon yapalım.

using System; // Temel sistem fonksiyonları için eklenir
using System.Collections.Generic; // Liste yapısı kullanmak için eklenir

public class Server // Sunucuyu temsil eden sınıf tanımlanır
{
    public string Name { get; set; } // Sunucu adı tutulur

    public void HandleRequest(string request) // Gelen isteği işleyen metot
    {
        Console.WriteLine($"{Name} isteği işledi: {request}"); // Hangi sunucunun isteği işlediği yazdırılır
    }
}

public class LoadBalancer // Load balancer sınıfı tanımlanır
{
    private List<Server> _servers; // Sunucu listesi tutulur
    private int _currentIndex = 0; // Round robin için index tutulur

    public LoadBalancer(List<Server> servers) // Constructor metot
    {
        _servers = servers; // Sunucu listesi atanır
    }

    public void HandleRequest(string request) // Gelen isteği yönlendiren metot
    {
        Server selectedServer = _servers[_currentIndex]; // Sıradaki sunucu seçilir

        selectedServer.HandleRequest(request); // İstek seçilen sunucuya gönderilir

        _currentIndex = (_currentIndex + 1) % _servers.Count; // Index artırılır ve liste başına döner
    }
}

public class Program // Ana program sınıfı
{
    public static void Main() // Program başlangıç noktası
    {
        var servers = new List<Server> // Sunucu listesi oluşturulur
        {
            new Server { Name = "Server A" }, // İlk sunucu
            new Server { Name = "Server B" }, // İkinci sunucu
            new Server { Name = "Server C" }  // Üçüncü sunucu
        };

        var loadBalancer = new LoadBalancer(servers); // Load balancer oluşturulur

        for (int i = 1; i <= 6; i++) // 6 adet istek simüle edilir
        {
            loadBalancer.HandleRequest("Request " + i); // Her istek load balancer'a gönderilir
        }
    }
}

Bu örnekte Round Robin algoritması kullanılır.

İstekler sırayla sunuculara dağıtılır.

Basit ama mantığı net gösterir.

En sık yapılan hatalar

  • Tek sunucuya güvenmek
  • Sticky session’a aşırı bağımlı olmak
  • Load balancer var diye her şey çözüldü sanmak
  • Sağlık kontrolü (health check) yapmamak

Buradaki health check, sunucunun çalışıp çalışmadığını kontrol etme mekanizmasıdır.

Sonuç

Load balancer:

  • Trafiği dağıtır
  • Sistemi hızlandırır
  • Çökme riskini azaltır
  • Ölçeklenebilirliği mümkün kılar

Ama asıl “vay be” noktası şudur:

Kullanıcı tek bir siteye girdiğini sanır.
Ama arka planda onlarca sunucu koordineli çalışıyordur.

İyi sistem tasarımı tam olarak budur:
karmaşıklığı sakmak, sadeliği göstermek.
