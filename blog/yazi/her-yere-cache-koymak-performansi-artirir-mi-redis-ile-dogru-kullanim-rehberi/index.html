Her Yere Cache Koymak Performansı Artırır mı? Redis ile Doğru Kullanım Rehberi

cache·22 Mart 2026·~8 dk okuma

Cache, yazılım dünyasında en çok konuşulan performans araçlarından biridir. Doğru kullanıldığında sistemi ciddi biçimde hızlandırır. Yanlış kullanıldığında ise kodu gereksiz yere karmaşıklaştırır, bellek tüketimini artırır ve bazı durumlarda uygulamayı daha da yavaşlatır.

Her yere cache koymak, otomatik olarak performans artışı sağlamaz. Hatta çoğu zaman, problemi çözmek yerine yeni problemler üretir. Bu yazıda cache’in ne işe yaradığını, ne zaman fayda sağladığını, ne zaman zarar verdiğini ve doğru kullanım için nelere dikkat edilmesi gerektiğini örneklerle inceleyelim.

Cache nedir?

Cache, sık kullanılan veriyi daha hızlı erişilebilen bir yerde geçici olarak saklama yöntemidir. Amaç, aynı veriyi her seferinde yeniden üretmek ya da yeniden sorgulamak yerine, hazır bir sonuç döndürmektir.

Örneğin bir veri tabanından her istekte aynı ürün listesini çekmek yerine, bu listeyi kısa süreliğine bellekte tutmak çoğu durumda daha hızlıdır. Çünkü bellek erişimi, veri tabanı erişiminden çok daha ucuzdur.

Buradaki temel fikir şudur:

  • Pahalı işlemi bir kez yap
  • Sonucu bir süre sakla
  • Aynı sonuç tekrar istendiğinde hızlıca geri dön

Bu mantık doğru yerde kullanılırsa çok etkilidir. Ancak her veri cache için uygun değildir.

Cache ne zaman fayda sağlar?

  • Aynı veri sık sık isteniyorsa
  • Veri çok sık değişmiyorsa
  • Veriyi üretmek pahalıysa
  • Dış servis çağrısı veya veri tabanı sorgusu maliyetliyse

Örneğin:

  • Ülke listesi
  • Sistem ayarları
  • Sık okunan ama nadiren değişen ürün kategorileri
  • Karmaşık rapor sonuçları

Bu tür verilerde cache ciddi kazanım sağlar. Çünkü aynı işi tekrar tekrar yapmak yerine, sonucu hazır tutmuş olursunuz.

Cache ne zaman zarar verir?

Cache’in zarar verdiği durumlar da oldukça yaygındır.

1. Veri çok sık değişiyorsa

Eğer veri sürekli güncelleniyorsa, cache eski bilgi döndürebilir. Bu da kullanıcıya yanlış veri gösterilmesine yol açar.

Örneğin bir kullanıcının profil adı değiştiğinde, eski adın bir süre daha görünmesi istenmeyen bir durumdur.

2. Cache yönetimi iyi yapılmıyorsa

Cache kullanmak sadece veriyi saklamak değildir. Aynı zamanda şunları da düşünmek gerekir:

  • Ne kadar süre saklanacak?
  • Ne zaman silinecek?
  • Hangi veri değişince cache temizlenecek?
  • Bellek dolarsa ne olacak?

Bu soruların cevabı net değilse, cache fayda yerine risk oluşturur.

3. Zaten hızlı olan işlemler cache’e uygun değildir

Bazen geliştiriciler her şeyi cache’lemeye çalışır. Oysa bazı sorgular zaten çok hızlıdır. Böyle bir durumda cache kontrolü yapmak, veriyi direkt almaktan bile daha maliyetli olabilir.

Yani cache her zaman hız kazandırmaz. Bazı durumlarda sadece ek katman oluşturur.

4. Bellek tüketimi artar

Büyük nesneleri veya çok fazla veriyi cache’e almak, bellek kullanımını ciddi biçimde artırabilir. Bu da uygulamanın genel performansını olumsuz etkileyebilir.

Özellikle bellek yönetiminin önemli olduğu sistemlerde bu konu dikkatle ele alınmalıdır.

Basit bir cache örneği

Aşağıdaki örnekte, ürün listesini bellekte saklayan basit bir yapı göreceksiniz.

using Microsoft.Extensions.Caching.Memory;

public class ProductService
{
    private readonly IMemoryCache _cache;

    public ProductService(IMemoryCache cache)
    {
        // Cache servisini dışarıdan alıyoruz
        _cache = cache;
    }

    public List<Product> GetProducts()
    {
        // Cache içinde bu veri için kullanacağımız anahtar
        var cacheKey = "product_list";

        // Eğer veri cache içinde varsa direkt geri döndür
        if (_cache.TryGetValue(cacheKey, out List<Product> products))
        {
            return products;
        }

        // Cache'te yoksa veriyi veri tabanından çek
        products = GetProductsFromDatabase();

        // Veriyi 5 dakika boyunca cache'te tut
        _cache.Set(cacheKey, products, TimeSpan.FromMinutes(5));

        return products;
    }

    private List<Product> GetProductsFromDatabase()
    {
        // Burada normalde veri tabanı sorgusu yapılır
        return new List<Product>
        {
            new Product { Id = 1, Name = "Kalem" },
            new Product { Id = 2, Name = "Defter" }
        };
    }
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
}

Bu kod ne yapıyor?

  • Önce cache’e bakıyor
  • Veri varsa direkt onu döndürüyor
  • Veri yoksa veri tabanından alıyor
  • Sonucu 5 dakika boyunca cache’te saklıyor

Bu yapı basit görünür ama temel mantığı çok önemlidir. Çünkü cache kullanımı, çoğu zaman tam olarak bu karar mekanizmasına dayanır.

Cache kullanırken en kritik konu: invalidation

Cache tarafındaki en zor problem, verinin ne zaman silineceğidir. Buna cache invalidation denir.

Örneğin ürün adı güncellendiğinde, cache içindeki eski ürün listesinin de temizlenmesi gerekir. Aksi halde kullanıcı eski veriyi görmeye devam eder.

Aşağıdaki örnek, ilgili cache kaydını temizlemeyi gösterir.

using Microsoft.Extensions.Caching.Memory;

public class ProductService
{
    private readonly IMemoryCache _cache;

    public ProductService(IMemoryCache cache)
    {
        // Cache servisini alıyoruz
        _cache = cache;
    }

    public void UpdateProduct(Product updatedProduct)
    {
        // Burada normalde ürün verisi veri tabanında güncellenir
        UpdateProductInDatabase(updatedProduct);

        // Ürün listesi cache'ini temizliyoruz
        _cache.Remove("product_list");
    }

    private void UpdateProductInDatabase(Product product)
    {
        // Gerçek projede veri tabanı güncellemesi yapılır
    }
}

Bu örnekte önemli nokta şudur: Veriyi güncelledikten sonra cache’i de temizlemek gerekir. Cache güncellenmezse, sistem eski veriyi göstermeye devam eder.

Her veriyi cache’lemek neden yanlış bir yaklaşımdır?

Cache’in amacı her şeyi saklamak değildir. Amacı, tekrar kullanım ihtimali yüksek olan ve üretimi maliyetli olan veriyi hızlandırmaktır.

Bir veriyi cache’e almadan önce şu sorular sorulmalıdır:

  • Bu veri ne kadar sık okunuyor?
  • Ne kadar sık değişiyor?
  • Üretimi pahalı mı?
  • Yanlış veya eski veri gösterilirse sorun olur mu?
  • Bellekte tutulması mantıklı mı?

Bu sorulara net cevap veremiyorsanız, cache çoğu zaman sezgisel değil, ölçüme dayalı olarak karar verilmesi gereken bir konudur.

Cache kullanırken yapılan yaygın hatalar

Cache tarafında en sık yapılan hatalardan bazıları şunlardır:

1) Süre belirlememek: Cache’e alınan verinin sonsuza kadar kalması, genelde yanlış bir yaklaşımdır.

2) Her istekte cache kontrolü yapıp hiçbir kazanç elde etmemek: Eğer veri zaten çok hızlı geliyorsa, cache sadece ek kod yükü getirir.

3) Büyük veri setlerini kontrolsüz saklamak: Bu durum bellek tüketimini gereksiz yere artırır.

4) Cache invalidation stratejisini düşünmemek: Eski verinin ne zaman silineceği planlanmazsa, sistem tutarsız davranır.

5) Her şeyi cache ile çözmeye çalışmak: Cache, iyi bir yardımcıdır. Ama mimarinin yerine geçmez.

Sonuç

Her yere cache koymak performansı artırmaz. Cache, doğru yerde kullanıldığında çok güçlü bir optimizasyon aracıdır. Yanlış yerde kullanıldığında ise uygulamayı daha karmaşık, daha hatalı ve bazı durumlarda daha yavaş hale getirir.

En doğru yaklaşım şudur: Cache’i alışkanlıkla değil, ihtiyaçla kullanmak.

Bir veriyi cache’lemeye karar vermeden önce şu dengeyi düşünmek gerekir:

  • Hız kazanımı
  • Bellek maliyeti
  • Veri doğruluğu
  • Yönetim karmaşıklığı

Eğer bu dengenin kazananı cache ise, kullanmak mantıklıdır. Değilse, cache sadece teknik bir süs olmaktan öteye geçmez.

Redis ve dağıtık cache neden önemlidir?

Tek sunuculu sistemlerde bellek cache yeterli olabilir. Ancak birden fazla sunucu kullanan sistemlerde aynı verinin her sunucuda ayrı ayrı tutulması sorun yaratır.

Bu noktada Redis gibi dağıtık cache çözümleri devreye girer. Böylece cache tek bir merkezi yerde tutulur ve tüm uygulama örnekleri aynı veriyi kullanır.

Redis Kullanımı

Önceki bölümde cache kullanımının her zaman performans kazancı sağlamadığını ve yanlış kullanıldığında ciddi problemlere yol açabileceğini gördük. Peki, cache’i doğru ve ölçeklenebilir şekilde kullanmak istediğimizde hangi araçlara yönelmeliyiz?

Bu noktada en yaygın çözümlerden biri Redis’tir.

Redis nedir?

Redis, bellek üzerinde çalışan, çok hızlı bir key-value veri saklama sistemidir. Genellikle cache katmanı olarak kullanılır.

Temel farkı şudur:

  • MemoryCache → sadece uygulamanın çalıştığı sunucuda yaşar
  • Redis → tüm uygulama instance’larının ortak kullandığı merkezi bir cache’tir

Bu sayede, birden fazla sunucudan oluşan sistemlerde veri tutarlılığı sağlanabilir.

Neden MemoryCache yerine Redis?

Tek sunuculu bir uygulamada MemoryCache yeterli olabilir. Ancak sistem büyüdüğünde bazı problemler ortaya çıkar:

  • Her sunucu kendi cache’ini tutar
  • Veriler senkron olmaz
  • Aynı veri birden fazla yerde tutulur
  • Cache temizleme işlemleri karmaşık hale gelir

Redis bu problemleri ortadan kaldırır çünkü cache tek bir merkezi noktada tutulur.

Redis ne zaman kullanılmalı?

Redis kullanmak her zaman doğru tercih değildir. Aşağıdaki senaryolarda anlamlıdır:

  • Uygulama birden fazla instance ile çalışıyorsa
  • Aynı cache verisinin tüm instance’lar tarafından paylaşılması gerekiyorsa
  • Yüksek trafikli sistemlerde performans kritikse
  • External API veya ağır sorgular sık kullanılıyorsa

Buna karşılık küçük ve tek sunuculu projelerde Redis gereksiz karmaşıklık oluşturabilir.

Redis ile basit cache kullanımı

Aşağıdaki örnek, Redis kullanarak kategori listesini cache’leyen basit bir yapıyı gösterir.

using Microsoft.Extensions.Caching.Distributed;
using System.Text.Json;

public class CategoryService
{
    private readonly IDistributedCache _cache;

    public CategoryService(IDistributedCache cache)
    {
        // Redis gibi dağıtık cache servislerini kullanmak için bu interface kullanılır
        _cache = cache;
    }

    public async Task<List<Category>> GetCategoriesAsync()
    {
        var cacheKey = "category_list";

        // Cache'ten string olarak veriyi almaya çalış
        var cachedData = await _cache.GetStringAsync(cacheKey);

        if (!string.IsNullOrEmpty(cachedData))
        {
            // Cache'te varsa JSON veriyi nesneye çevirip döndür
            return JsonSerializer.Deserialize<List<Category>>(cachedData);
        }

        // Cache'te yoksa veri tabanından çek
        var categories = await GetCategoriesFromDatabaseAsync();

        // Nesneyi JSON formatına çevir
        var serializedData = JsonSerializer.Serialize(categories);

        var options = new DistributedCacheEntryOptions
        {
            // Veriyi 10 dakika boyunca sakla
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
        };

        // Veriyi Redis'e yaz
        await _cache.SetStringAsync(cacheKey, serializedData, options);

        return categories;
    }

    private Task<List<Category>> GetCategoriesFromDatabaseAsync()
    {
        // Gerçek projede burada veri tabanı sorgusu olur
        return Task.FromResult(new List<Category>
        {
            new Category { Id = 1, Name = "Elektronik" },
            new Category { Id = 2, Name = "Kırtasiye" }
        });
    }
}

public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }
}

Bu örnekte yapılan işlemler:

  • Önce Redis’te veri var mı kontrol edilir
  • Varsa direkt cache’ten döndürülür
  • Yoksa veri tabanından çekilir
  • Sonuç Redis’e yazılır
  • Belirli bir süre boyunca tekrar kullanılmak üzere saklanır

Redis kullanırken dikkat edilmesi gerekenler

Redis güçlü bir araçtır ama yanlış kullanımı ciddi problemlere yol açabilir.

1. Cache süresi (TTL) doğru belirlenmelidir

Çok uzun süre: Eski veri riski artar.

Çok kısa süre: Cache’in faydası azalır.

Bu yüzden veri tipine göre süre belirlemek gerekir.

2. Cache invalidation stratejisi şarttır

Veri güncellendiğinde Redis’teki karşılığının da temizlenmesi gerekir. Aksi halde sistem eski veri döndürür.

3. Büyük verileri cache’lemek risklidir

Redis bellek tabanlı çalışır. Büyük veri setleri:

  • Maliyet artırır
  • Performansı düşürebilir

4. Cache her problemi çözmez

Redis kullanmak, kötü yazılmış bir sorguyu sihirli şekilde düzeltmez. Önce veri tabanı ve algoritma doğru olmalıdır.

Sonuç

Redis, cache kullanımını ölçeklenebilir hale getiren güçlü bir araçtır. Ancak tek başına bir çözüm değildir.

Doğru yaklaşım şudur:

  • Önce problemi doğru analiz et
  • Cache gerçekten gerekli mi karar ver
  • Gerekliyse doğru strateji ile uygula
  • Küçük sistemlerde basit kal, büyük sistemlerde Redis kullan

Cache ve Redis birlikte kullanıldığında ciddi performans kazanımı sağlar. Ancak yanlış kullanıldığında, sadece sistemi karmaşıklaştırır.
