C# Async/Await — Modern .NET (Core) için yanlış bilinen 5 şey

csharp·15 Mart 2026·~4 dk okuma

Modern .NET (ör. .NET 6/7/8 ve sonrası) ile bazı davranışlar daha net ama yanlış kavrayışlar hala performans, hata yönetimi ve ölçeklenebilirlik sorunlarına yol açıyor. Aşağıda en sık karıştırılan 5 nokta’yı modern .NET perspektifiyle, anlamayanlar için gereken kısa tanımlarla birlikte açıklıyorum.

1) async = paralel çalışma değildir

Ne demek? async anahtar kelimesi bir metodun içinde await kullanılacağını işaretler; bu, metodun çağrıldığı thread’i otomatik olarak paralel veya yeni bir thread'e taşımayacağı anlamına gelir. await asıl işi yapan görev (Task) tamamlanana kadar çağırana kontrolü geri verir — ama eğer await'leri ardışık yazarsanız işler ardışık (sequential) çalışır.

Örnek — ardışık (yavaş) vs paralel (hızlı)

// Ardışık: iki HTTP isteği sırayla yapılır → toplam süre = A + B
async Task<string[]> FetchSequentialAsync()
{
    // Modern HttpClient kullanımı örneği
    var a = await httpClient.GetStringAsync("https://service-a/api/").ConfigureAwait(false);
    var b = await httpClient.GetStringAsync("https://service-b/api/").ConfigureAwait(false);
    return new[] { a, b };
}

// Paralel: iki istek aynı anda başlar → toplam süre ≈ max(A, B)
async Task<string[]> FetchParallelAsync()
{
    var taskA = httpClient.GetStringAsync("https://service-a/api/"); // hemen başlar
    var taskB = httpClient.GetStringAsync("https://service-b/api/"); // hemen başlar
    var results = await Task.WhenAll(taskA, taskB).ConfigureAwait(false);
    return results;
}

Not: ConfigureAwait(false) daha sonra neden kullanıldığını ayrıca açıklayacağım.

2) async void neredeyse her zaman yanlıştır

Ne demek? async void metotlar Task döndürmez; çağıran tarafından await edilemez ve oluşan istisnalar normal akışa düşmez. Modern server-side kodda (ASP.NET Core, background service, console app) async void kullanmak hatadır.

Neden kötü?

  • Hata yönetimi: async void içindeki exception, çağıranın try/catch'ine gelmez.
  • Test edilebilirlik ve yaşam döngüsü kontrolü zorlaşır.

Doğru kullanım

// Yanlış
async void FireAndForget() { await Task.Delay(1000); throw new Exception("boom"); }

// Doğru
async Task FireAsync()
{
    await Task.Delay(1000);
    throw new Exception("boom");
}

// Çağıran kod
try
{
    await FireAsync();
}
catch (Exception ex)
{
    // Hata burada güvenle yakalanır
}

3) .Result / .Wait() kullanmak yalnızca deadlock değil — thread pool tükenmesine de sebep olabilir

Kavram açıklaması:

  • ThreadPool: .NET’in arka planda çalışan, kısa ömürlü görevleri çalıştırmak için yönettiği thread havuzu.
  • Deadlock: İki veya daha fazla işlem birbirinin tamamlanmasını bekleyip hiç başaramaması.
  • Thread starvation (thread havuzu tükenmesi): Uzun süreli, bloklayan (synchronous) işlemler threadleri uzun süre işgal edince yeni işler beklemek zorunda kalır; bu da istek gecikmelerine veya hatalara neden olur.

Örnek (ASP.NET Core / background): neden .Result tehlikeli?

// Kötü: blocking call — thread pool thread'i bloklar
public IActionResult SyncAction()
{
    // Burada GetDataAsync().Result çağrısı mevcut thread'i bloklar
    var data = _service.GetDataAsync().Result;
    return Ok(data);
}

ASP.NET Core klasik bir SynchronizationContext kullanmaz; ama .Result veya .Wait() ile uzun süreli bloklama thread pool kaynaklarını tüketerek sistemin ölçeklenmesini bozar.

Çözüm: çağıran kodu da async yap ve await kullan.

public async Task<IActionResult> AsyncAction()
{
    var data = await _service.GetDataAsync(); // non-blocking
    return Ok(data);
}

4) ConfigureAwait(false) ne işe yarar ve ne zaman kullanmalı?

Tanım: ConfigureAwait(false) — await işleminden sonra kodun orijinal synchronization context’ine (bağlama) dönmesini engeller. Bu, genelde performansı iyileştirir ve deadlock riskini azaltır.

Nerede kullanmalı?

  • Kütüphane / servis katmanı: UI/HTTP context ile tekrar etkileşime girmeyeceksen ConfigureAwait(false) koy. Bu, çağıranın bağlamını yakalamayı önler ve bazı senaryolarda gereksiz context switch’leri engeller.
  • Controller / middleware / UI: await sonrası HTTP context (HttpContext) veya UI ile iş yapacaksan ConfigureAwait(false) kullanma — bağlamı kaybetmemelisin.

Örnek:

// Kütüphane/metod: ConfigureAwait(false) iyi bir tercih
public async Task<string> GetFromRemoteAsync(string url)
{
    var s = await httpClient.GetStringAsync(url).ConfigureAwait(false);
    return s;
}

5) Hata fırlatma davranışı: await ile doğrudan istisna, .Wait()/.Result ile AggregateException

Ne demek? await edilen bir Task hata verirse doğrudan o istisna fırlatılır. Ancak Task.Wait() veya .Result kullanırsan, .NET bu hataları bir AggregateException içine sarar; gerçek hata InnerException'da olur.

Örnek:

async Task ThrowerAsync()
{
    await Task.Delay(1);
    throw new InvalidOperationException("bir şey ters gitti");
}

void WaitExample()
{
    try
    {
        ThrowerAsync().Wait(); // AggregateException atar
    }
    catch (AggregateException a)
    {
        Console.WriteLine(a.InnerException.Message);
    }
}

async Task AwaitExample()
{
    try
    {
        await ThrowerAsync(); // doğrudan InvalidOperationException yakalanır
    }
    catch (InvalidOperationException ex)
    {
        Console.WriteLine(ex.Message);
    }
}

Pratik: await ile çalış; daha temiz ve anlaşılır hata yönetimi sağlar.

Ekstra: ValueTask nedir ve ne zaman düşünmeli?

Tanım: ValueTask<T> bir Task<T> alternatifidir; kısa ömürlü, sıkça başarılı dönüş yapan asenkron metotlarda altta gereksiz Task nesnesi tahsisini azaltmak için kullanılır. Ancak kullanım karmaşıklığı getirir; yalnızca performans profili yaptığında ve GC/alloc azalımı gerekiyorsa tercih et.

Özet — Modern .NET için kısa checklist

  • Tüm katmanlarda “async all the way” prensibini uyguluyor muyum? (controller → service → repository)
  • Blocking ( .Result / .Wait() / Thread.Sleep) kullanmaktan kaçınıyor muyum?
  • Paralel yapılması gereken IO çağrılarını Task.WhenAll ile mi çalıştırıyorum?
  • Kütüphane/metod seviyesinde ConfigureAwait(false) düşünüldü mü?
  • async void yalnızca gerçekten objektif bir sebeple (ör. framework event handler) kullanılıyor mu?
  • Hata yönetimini await üzerinden yapıyor muyum (AggregateException ile uğraşmamak için)?

Modern .NET projelerinde async/await doğru kullanıldığında ölçeklenebilirlik ve kaynak verimliliği sağlar. Ancak yanlış kullanım (bloklama, ardışık awaits, async void) aynı zamanda uygulamanızı yavaşlatır, belirsiz hatalar üretir veya thread havuzunu tüketir. Önce mimariyi async olacak şekilde planlayın; sonra kodu performans profili ile kontrol edin.
