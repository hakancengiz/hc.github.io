.NET Core’da Controller, Routing, DTO ve Validation ile Güçlü API Tasarımı

Web API Nedir?

Web API (Application Programming Interface), uygulamalar arasında veri alışverişini sağlayan bir arabirimdir.
Bir kullanıcı arayüzü yerine, HTTP protokolü üzerinden veri döner.

Örnek:
Bir mobil uygulama, arka plandaki sunucudan veriyi API çağrısı ile alır.
Tarayıcıda görmesek bile, her işlem GET, POST, PUT, DELETE gibi HTTP metotlarıyla yapılır.

ASP.NET Core Web API’nin Mimarisi

Bir Web API projesinde temel yapı şöyledir;

📁 MyApp
 ┣ 📂 Controllers     → İstekleri karşılayan sınıflar
 ┣ 📂 Services        → İş mantığı
 ┣ 📂 Repositories    → Veritabanı erişimi
 ┣ 📂 Models / DTOs   → Veri transfer objeleri
 ┗ Program.cs         → Uygulamanın giriş noktası

Her katman kendi sorumluluğunu taşır:

  • Controller: İstekleri alır, doğru servise yönlendirir.
  • Service: İş kurallarını uygular.
  • Repository: Veritabanı işlemlerini yapar.

Controller Mantığı

Controller, Web API’nin beyni gibidir.
Her HTTP isteği (GET, POST, PUT, DELETE) bir Action metoduna yönlendirilir.

Aşağıda örnek bir kullanıcı API’si görebilirsin

// API/Controllers/UserController.cs
// Kullanıcı işlemlerini yöneten Web API controller sınıfı

// [ApiController]: Otomatik model doğrulama, HTTP yanıt dönüşü gibi kolaylıklar sağlar
// [Route]: Bu controller’ın temel URL adresini tanımlar
[ApiController]
[Route("api/[controller]")]
public class UserController : ControllerBase
{
    // Servis katmanını temsil eden arayüz
    private readonly IUserService _userService;

    // Dependency Injection ile servis enjekte edilir
    public UserController(IUserService userService)
    {
        _userService = userService;
    }

    // HTTP GET isteğini karşılar: /api/user
    [HttpGet]
    public async Task<IActionResult> GetUsers()
    {
        // Servis katmanından tüm kullanıcıları alır
        var users = await _userService.GetActiveUsersAsync();

        // 200 OK yanıtı döner ve veriyi JSON olarak gönderir
        return Ok(users);
    }

    // HTTP GET isteğiyle belirli bir kullanıcıyı getirir: /api/user/5
    [HttpGet("{id}")]
    public async Task<IActionResult> GetUserById(int id)
    {
        // Servisten kullanıcıyı getirir
        var user = await _userService.GetByIdAsync(id);

        // Eğer kullanıcı yoksa 404 Not Found döner
        if (user == null)
            return NotFound($"Kullanıcı bulunamadı: {id}");

        // Aksi halde 200 OK ile kullanıcıyı döner
        return Ok(user);
    }

    // HTTP POST isteğiyle yeni kullanıcı ekler
    [HttpPost]
    public async Task<IActionResult> AddUser(UserDto userDto)
    {
        // Servis katmanına DTO’yu iletir
        await _userService.AddAsync(userDto);

        // 201 Created yanıtı döner
        return CreatedAtAction(nameof(GetUserById), new { id = userDto.Id }, userDto);
    }

    // HTTP DELETE isteğiyle kullanıcı siler
    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteUser(int id)
    {
        // Servisten silme işlemini yapar
        var result = await _userService.DeleteAsync(id);

        // Başarısızsa 404 döner
        if (!result)
            return NotFound("Kullanıcı bulunamadı.");

        // Başarılıysa 204 No Content döner
        return NoContent();
    }
}

DTO (Data Transfer Object)

DTO, katmanlar arası veri taşımak için kullanılır.
Entity modellerini doğrudan istemciye döndürmek yerine DTO kullanmak, veri gizliliğini ve kontrolünü artırır.

// Entities/DTOs/UserDto.cs
// API’de dış dünyaya sunulan kullanıcı modeli
public class UserDto
{
    // ID sunulabilir
    public int Id { get; set; }

    // İsim zorunlu bir alandır
    public string Name { get; set; } = string.Empty;

    // E-posta, kullanıcı doğrulama işlemlerinde kullanılır
    public string Email { get; set; } = string.Empty;
}

DTO Kullanmanın Faydaları

Veri dönüşlerini sadeleştirir
Güvenlik ve performans artar

Model Validation (Doğrulama)

ASP.NET Core, veri doğrulamasını DataAnnotations aracılığıyla sağlar.
DTO üzerinde doğrudan yapılabilir;

// Entities/DTOs/UserDto.cs
// Kullanıcı ekleme sırasında model doğrulama örneği
public class CreateUserDto
{
    [Required(ErrorMessage = "Ad alanı zorunludur.")]
    [MaxLength(50, ErrorMessage = "Ad 50 karakterden uzun olamaz.")]
    public string Name { get; set; } = string.Empty;

    [Required(ErrorMessage = "E-posta adresi zorunludur.")]
    [EmailAddress(ErrorMessage = "Geçerli bir e-posta adresi girin.")]
    public string Email { get; set; } = string.Empty;
}

Eğer model geçersizse, [ApiController] özelliği sayesinde
framework otomatik olarak 400 Bad Request döner.

Routing Mantığı

Routing, HTTP isteğinin hangi metoda yönlendirileceğini belirler.
ASP.NET Core’da [Route] ve [Http...] öznitelikleriyle tanımlanır.

// /api/user → GetUsers()
// /api/user/5 → GetUserById()
// /api/user → AddUser()
// /api/user/5 → DeleteUser()

Ayrıca özel route tanımlamak da mümkündür;

[HttpGet("byemail/{email}")]
public async Task<IActionResult> GetUserByEmail(string email)
{
    var user = await _userService.GetByEmailAsync(email);
    if (user == null)
        return NotFound();
    return Ok(user);
}

Middleware: İsteklerin Geçtiği Filtre Zinciri

Middleware, gelen isteklerin geçtiği ara katmanlardır.
Örneğin loglama, hata yönetimi veya kimlik doğrulama gibi işlemler burada yapılır.

// Program.cs
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();

var app = builder.Build();

// 1️⃣ Hata yönetimi
app.UseExceptionHandler("/error");

// 2️⃣ HTTPS yönlendirmesi
app.UseHttpsRedirection();

// 3️⃣ Yetkilendirme kontrolü
app.UseAuthorization();

// 4️⃣ Controller endpoint'lerini aktif et
app.MapControllers();

app.Run();

Middleware zinciri, istek geldiğinde sırasıyla çalışır.
Her biri isteği işleyebilir veya bir sonrakine aktarabilir.

HTTP Status Kodları

| Kod | Anlamı                | Açıklama               |
| --- | --------------------- | ---------------------- |
| 200 | OK                    | Başarılı işlem         |
| 201 | Created               | Yeni kayıt oluşturuldu |
| 204 | No Content            | Başarılı ama veri yok  |
| 400 | Bad Request           | Hatalı istek           |
| 404 | Not Found             | Kayıt bulunamadı       |
| 500 | Internal Server Error | Sunucu hatası          |

Bu kodlar sayesinde istemci, API’nin ne yaptığını net şekilde anlar.
