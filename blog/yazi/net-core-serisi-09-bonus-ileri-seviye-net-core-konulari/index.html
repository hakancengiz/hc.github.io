1. Custom Middleware — Akışı Kontrol Etmenin Gücü

Middleware, bir isteğin API’ye ulaşmadan önce geçtiği ara katmanlardır.
İsteği yakalayabilir, yönlendirebilir veya loglayabilirsin.

// Middleware/RequestLoggingMiddleware.cs
// Her isteği loglayan özel middleware
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;

    public RequestLoggingMiddleware(RequestDelegate next, ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 1️⃣ İstek zamanı
        var start = DateTime.Now;

        // 2️⃣ İstek bilgilerini logla
        _logger.LogInformation($"İstek: {context.Request.Method} {context.Request.Path}");

        // 3️⃣ Zincirdeki bir sonraki middleware'e geç
        await _next(context);

        // 4️⃣ Yanıt süresini hesapla
        var duration = DateTime.Now - start;
        _logger.LogInformation($"Yanıt süresi: {duration.TotalMilliseconds} ms");
    }
}

Kayıt:

// Program.cs
app.UseMiddleware<RequestLoggingMiddleware>();

Gerçek Senaryo:
Bu yapı, API performansını izlemek ve gereksiz sorguları tespit etmek için harikadır.

2. Action Filters — Controller Seviyesinde Otomasyon

Filters, Controller veya Action seviyesinde önce / sonra çalıştırılacak işlemleri tanımlar. Örneğin her API çağrısından önce kimlik kontrolü, sonra loglama yapılabilir.

// Filters/ExecutionTimeFilter.cs
// Her Action'ın çalışma süresini ölçen filter
public class ExecutionTimeFilter : IActionFilter
{
    private readonly ILogger<ExecutionTimeFilter> _logger;
    private Stopwatch _stopwatch;

    public ExecutionTimeFilter(ILogger<ExecutionTimeFilter> logger)
    {
        _logger = logger;
    }

    public void OnActionExecuting(ActionExecutingContext context)
    {
        // Action başlamadan süreyi başlat
        _stopwatch = Stopwatch.StartNew();
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        // Action bittikten sonra süreyi durdur
        _stopwatch.Stop();
        _logger.LogInformation($"[{context.ActionDescriptor.DisplayName}] { _stopwatch.ElapsedMilliseconds } ms sürdü.");
    }
}

Kayıt:

// Program.cs
builder.Services.AddControllers(options =>
{
    options.Filters.Add<ExecutionTimeFilter>();
});

Avantaj:
Loglama, performans takibi, validasyon gibi işler controller koduna dağılmaz.

3. Background Jobs — Arka Plan Görevleri (Hangfire)

Bazı işler kullanıcıyı bekletmeden arka planda yapılmalıdır.
Örneğin: e-posta gönderimi, log arşivleme, rapor oluşturma gibi.

Hangfire kurulumu

dotnet add package Hangfire
dotnet add package Hangfire.AspNetCore

Kullanım:

// Program.cs
builder.Services.AddHangfire(x => x.UseSqlServerStorage("Server=.;Database=MyApp;Trusted_Connection=True;"));
builder.Services.AddHangfireServer();

app.UseHangfireDashboard(); // /hangfire adresinden izlenebilir

// Arka plan işi tanımlama
BackgroundJob.Enqueue(() => Console.WriteLine("Rapor gönderildi!"));

Avantaj: Kuyruk sistemiyle zamanlanmış görevler oluşturabilir, tekrar eden işleri planlayabilirsin.

4. CQRS & Mediator Pattern — Okuma ve Yazma Ayrımı

Gerçek hayatta büyük sistemlerde okuma (query) ve yazma (command) işlemleri farklı katmanlarda ele alınır. Bu prensip CQRS (Command Query Responsibility Segregation) olarak bilinir.

Örnek:

// Application/Commands/CreateUserCommand.cs
public record CreateUserCommand(string Name, string Email) : IRequest<User>;

Handler:

// Application/Handlers/CreateUserHandler.cs
public class CreateUserHandler : IRequestHandler<CreateUserCommand, User>
{
    private readonly IUserRepository _repository;

    public CreateUserHandler(IUserRepository repository)
    {
        _repository = repository;
    }

    public async Task<User> Handle(CreateUserCommand request, CancellationToken cancellationToken)
    {
        // 1️⃣ Yeni kullanıcı oluştur
        var user = new User { Name = request.Name, Email = request.Email };

        // 2️⃣ Veritabanına ekle
        await _repository.AddAsync(user);

        // 3️⃣ Kaydı geri döndür
        return user;
    }
}

CQRS genellikle MediatR kütüphanesiyle kullanılır:

dotnet add package MediatR

Avantajlar:

  • Kodun sorumlulukları ayrılır
  • Test etmek kolaylaşır
  • Okuma/yazma trafiği optimize edilir

5. SignalR — Gerçek Zamanlı İletişim

SignalR, WebSocket tabanlı gerçek zamanlı mesajlaşma altyapısıdır.
Örneğin:

  • Canlı bildirimler
  • Dashboard verileri
  • Chat uygulamaları

Örnek:

// Hubs/NotificationHub.cs
public class NotificationHub : Hub
{
    // İstemciye mesaj gönderen metod
    public async Task SendMessage(string user, string message)
    {
        await Clients.All.SendAsync("ReceiveMessage", user, message);
    }
}

Program.cs:

builder.Services.AddSignalR();

app.MapHub<NotificationHub>("/hubs/notification");

Frontend (JavaScript):

const connection = new signalR.HubConnectionBuilder()
    .withUrl("/hubs/notification")
    .build();

connection.on("ReceiveMessage", (user, message) => {
    console.log(`${user}: ${message}`);
});

connection.start();

Gerçek Senaryo:
Admin panelinde canlı işlem akışı, borsa ekranı, mesajlaşma vb.

6. API Versioning

Gerçek dünyada API’ler zamanla değişir.
Yeni sürümler, eski istemcilerle uyumlu olmalıdır.

// Program.cs
builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;
    options.ReportApiVersions = true;
});

Controller:

// v1
[ApiVersion("1.0")]
[Route("api/v{version:apiVersion}/user")]
public class UserV1Controller : ControllerBase
{
    [HttpGet]
    public IActionResult Get() => Ok("V1: Eski versiyon kullanıcı listesi");
}

// v2
[ApiVersion("2.0")]
[Route("api/v{version:apiVersion}/user")]
public class UserV2Controller : ControllerBase
{
    [HttpGet]
    public IActionResult Get() => Ok("V2: Gelişmiş kullanıcı listesi");
}

İstemci, api/v1/user veya api/v2/user çağırarak istediği sürümü seçebilir.

7. Performans İzleme (Application Insights)

Uygulamanın “ne kadar hızlı” ve “nerede takıldığını” ölçmek için Application Insights kullanılabilir.

dotnet add package Microsoft.ApplicationInsights.AspNetCore
// Program.cs
builder.Services.AddApplicationInsightsTelemetry();

Bu sistem:

  • Her isteğin süresini ölçer
  • Hataları ve SQL sorgu sürelerini loglar
  • Azure portalından canlı izlenebilir
