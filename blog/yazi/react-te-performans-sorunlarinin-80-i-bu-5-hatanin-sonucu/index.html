React’te Performans Sorunlarının %80’i Bu 5 Hatanın Sonucu

react·1 Nisan 2026·~8 dk okuma

React güçlü bir yapı. Doğru kullanıldığında hızlı, düzenli ve bakım açısından rahat bir uygulama kurmanı sağlar. Ama işin zor tarafı şu: React’te performans problemi çoğu zaman framework’ün kendisinden değil, geliştiricinin yaptığı küçük ama etkili hatalardan çıkar.

İlk bakışta uygulama düzgün çalışıyor gibi görünür. Sayfalar açılır, butonlar tepki verir, veriler ekrana gelir. Fakat veri büyüdükçe, component sayısı arttıkça ve kullanıcı etkileşimi yoğunlaştıkça sistem ağırlaşmaya başlar. İşte o noktada problem görünür olur.

1) Gereksiz yeniden render üretmek

React’te en temel kavramlardan biri render’dır. Render, component’in ekrana nasıl çizileceği anlamına gelir. Bir component yeniden render olduğunda, React o component’in çıktısını yeniden hesaplar.

Buradaki sorun şu: Her yeniden render kötü değildir. Ama gereksiz yeniden render sayısı arttıkça uygulama yavaşlar.

En sık yapılan hata, state’i yanlış yerde tutmak veya her değişiklikte tüm component ağacını tekrar çalıştırmaktır. Özellikle üst component’te tuttuğun küçük bir state, alttaki birçok child component’i de gereksiz yere yeniden çalıştırabilir.

Yanlış örnek

import React, { useState } from "react";

function App() {
  const [text, setText] = useState("");

  return (
    <div>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)} // Her tuşta state değişir ve component yeniden render olur
      />
      <HeavyList /> {/* Bu component, input ile ilgisi olmasa bile tekrar render olabilir */}
    </div>
  );
}

function HeavyList() {
  const items = Array.from({ length: 10000 }, (_, i) => i);

  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default App;

Bu örnekte input’a her harf yazıldığında App yeniden render olur. Bu da HeavyList’in tekrar hesaplanmasına yol açabilir. HeavyList çok ağırsa, kullanıcı gecikme hisseder.

Doğru yaklaşım

Ağır çalışan bölümü ayrıştırmak ve sadece gerektiğinde render etmek gerekir.

import React, { useState, memo } from "react";

function App() {
  const [text, setText] = useState("");

  return (
    <div>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)} // Sadece input state'i değişiyor
      />
      <HeavyList /> {/* memo ile sarıldığında gereksiz render'lar azaltılabilir */}
    </div>
  );
}

const HeavyList = memo(function HeavyList() {
  const items = Array.from({ length: 10000 }, (_, i) => i);

  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
});

export default App;

Buradaki memo, bir component’in props’ları değişmedikçe tekrar render olmasını engellemeye yardımcı olur. Bu işleme memoization denir. Memoization, daha önce hesaplanmış sonucu saklayıp aynı hesaplamayı tekrar yapmamak demektir.

2) Aynı fonksiyonları ve nesneleri her render’da yeniden oluşturmak

React’te bir component her render olduğunda, içindeki fonksiyonlar ve nesneler de yeniden oluşturulur. Bu durum çoğu zaman fark edilmez ama özellikle child component’lere props olarak verilen fonksiyonlarda ciddi sorun çıkarabilir.

Örneğin onClick, onChange gibi callback fonksiyonlarını her render’da yeniden tanımlarsan, child component “prop değişti” diye tekrar render olabilir.

Yanlış örnek

import React, { useState, memo } from "react";

function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1); // Her render'da yeni bir fonksiyon referansı oluşur
  };

  return (
    <div>
      <button onClick={handleClick}>Arttır</button>
      <Child onAction={handleClick} />
    </div>
  );
}

const Child = memo(function Child({ onAction }) {
  return (
    <button onClick={onAction}>
      Child Butonu
    </button>
  );
});

export default Parent;

Burada Child component’i memo ile sarılmış olsa bile, handleClick her render’da yeni bir referans olduğu için child tekrar render olabilir.

Doğru yaklaşım

useCallback kullanmak bu durumda faydalıdır. useCallback, bir fonksiyonun referansını belirli bağımlılıklar değişmedikçe sabit tutar.

import React, { useState, useCallback, memo } from "react";

function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    setCount((prev) => prev + 1); // Önceki değeri kullanmak daha güvenlidir
  }, []); // Bağımlılık boş olduğu için fonksiyon referansı sabit kalır

  return (
    <div>
      <button onClick={handleClick}>Arttır</button>
      <Child onAction={handleClick} />
    </div>
  );
}

const Child = memo(function Child({ onAction }) {
  return <button onClick={onAction}>Child Butonu</button>;
});

export default Parent;

Buradaki önemli terim şu: referans. JavaScript’te iki nesne veya fonksiyon dışarıdan aynı görünse bile, bellekte farklı referanslara sahip olabilir. React da çoğu zaman bunu kontrol eder.

3) Büyük listeleri tek seferde ekrana basmak

Bir listedeki öğe sayısı azsa sorun olmaz. Ama yüzlerce ya da binlerce satır render ediyorsan performans düşebilir. Özellikle tablo, ürün listesi, mesaj ekranı, log görünümü gibi alanlarda bu çok sık yaşanır.

Bu durumda kullanılan kavramlardan biri virtualization’dır. Virtualization, sadece ekranda görünür olan elemanları render etmek anlamına gelir. Yani listedeki tüm öğeleri aynı anda çizmek yerine, kullanıcı hangi kısmı görüyorsa sadece o kısmı üretirsin.

Yanlış yaklaşım

function BigList({ items }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>
          {item.name}
        </li>
      ))}
    </ul>
  );
}

Bu yapı küçük listelerde sorun çıkarmaz. Ama 10.000 öğe varsa, hepsini tek seferde DOM’a basmak kullanıcı deneyimini ağırlaştırabilir.

DOM, tarayıcının sayfadaki elemanları tuttuğu yapı anlamına gelir. DOM büyüdükçe tarayıcının işi zorlaşır.

Daha doğru yaklaşım

Gerçek projelerde bunun için react-window veya react-virtualized gibi kütüphaneler kullanılır. Aşağıda mantığı göstermek için sade bir örnek var:

import React from "react";

function SimpleVirtualLikeList({ items, startIndex, visibleCount }) {
  const visibleItems = items.slice(startIndex, startIndex + visibleCount); // Sadece görünen kısmı alıyoruz

  return (
    <ul>
      {visibleItems.map((item) => (
        <li key={item.id}>
          {item.name} {/* Ekranda yalnızca bu aralıktaki elemanlar çizilir */}
        </li>
      ))}
    </ul>
  );
}

export default SimpleVirtualLikeList;

Bu gerçek bir virtualization kütüphanesi kadar gelişmiş değildir ama mantığı anlatır: Hepsini render etme, yalnızca görünen kısmı çiz.

4) useEffect’i yanlış kullanmak

useEffect, React’te yan etki yönetmek için kullanılır. Yan etki derken kastedilen şey, component’in doğrudan render sürecine ait olmayan ama sonradan yapılması gereken işlerdir. Örneğin veri çekmek, event listener eklemek, localStorage okumak gibi işlemler.

Sorun şu: useEffect yanlış dependency ile kullanılırsa gereksiz tekrar çalışır. Dependency, effect’in hangi değerler değişince yeniden çalışacağını belirleyen listedir.

Yanlış örnek

import React, { useState, useEffect } from "react";

function UserList() {
  const [users, setUsers] = useState([]);
  const [search, setSearch] = useState("");

  useEffect(() => {
    fetch("/api/users")
      .then((res) => res.json())
      .then((data) => setUsers(data)); // Bu effect yanlışlıkla gereksiz yere tekrar çalışabilir
  }, [users]); // users değişince tekrar çalışır, bu da döngü yaratabilir

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)} // Arama alanı sadece state güncelliyor
      />
      <ul>
        {users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </div>
  );
}

export default UserList;

Burada users dependency olarak verildiği için users güncellenince effect tekrar çalışır. Bu da tekrar fetch atılmasına ve hatta sonsuz döngüye kadar gidebilir.

Doğru kullanım

import React, { useState, useEffect } from "react";

function UserList() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    fetch("/api/users")
      .then((res) => res.json())
      .then((data) => setUsers(data)); // Veri yalnızca component ilk yüklendiğinde çekilir
  }, []); // Boş bağımlılık listesi = sadece ilk render sonrası çalışır

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

export default UserList;

Buradaki temel hata çoğu zaman şudur: useEffect “ne zaman çalışmalı?” sorusuna net cevap vermeden kullanılır. Bu da performans sorunlarına ve gereksiz ağ isteğine yol açar.

5) State’i yanlış yerde tutmak

React’te state, component’in değişen verisini tutar. Ama state’i nereye koyduğun çok önemlidir. Çünkü state hangi component’te tutuluyorsa, o component ve onun altındaki tüm component’ler yeniden render olabilir.

En sık yapılan hata, çok küçük bir değişkeni en üst seviyede tutmaktır. Bu durumda sistem gereksiz yere geniş bir alanı yeniden çalıştırır.

Yanlış örnek

import React, { useState } from "react";

function App() {
  const [inputValue, setInputValue] = useState(""); // Küçük bir state en üstte tutuluyor

  return (
    <div>
      <SearchBox value={inputValue} onChange={setInputValue} />
      <ExpensiveSection /> {/* Input değiştikçe bu bölüm de etkilenebilir */}
    </div>
  );
}

function SearchBox({ value, onChange }) {
  return (
    <input
      value={value}
      onChange={(e) => onChange(e.target.value)} // Her yazışta üst state güncelleniyor
    />
  );
}

function ExpensiveSection() {
  const items = Array.from({ length: 5000 }, (_, i) => i);

  return (
    <div>
      {items.map((item) => (
        <p key={item}>{item}</p>
      ))}
    </div>
  );
}

export default App;

Buradaki sorun şu: inputValue yalnızca arama kutusunu ilgilendiriyor ama en üstte tutulduğu için daha geniş alanı etkiliyor.

Daha iyi yaklaşım

State’i sadece ihtiyaç duyulan yerde tutmak gerekir.

import React, { useState } from "react";

function App() {
  return (
    <div>
      <SearchBox />
      <ExpensiveSection />
    </div>
  );
}

function SearchBox() {
  const [value, setValue] = useState(""); // State sadece bu component'e ait

  return (
    <input
      value={value}
      onChange={(e) => setValue(e.target.value)} // Sadece bu alan yeniden çalışır
    />
  );
}

function ExpensiveSection() {
  const items = Array.from({ length: 5000 }, (_, i) => i);

  return (
    <div>
      {items.map((item) => (
        <p key={item}>{item}</p>
      ))}
    </div>
  );
}

export default App;

Bu yaklaşımda arama kutusu değişse bile ağır çalışan bölüm doğrudan etkilenmez.

Bu beş hata neden bu kadar yaygın?

Çünkü React başlangıçta çok kolay görünür. Component yazarsın, state eklersin, ekrana basarsın. Uygulama çalışınca her şey yolunda sanırsın. Ama performans problemleri genellikle “çalışmıyor” diye bağırmaz. Sessiz gelir.

Bir uygulama şunları yapıyorsa bu hatalardan birini yaşıyor olma ihtimali yüksektir:

  • yazı yazarken gecikme hissediliyorsa,
  • liste kaydırılırken kasıyorsa,
  • bir butona basınca fazla bölüm yeniden çalışıyorsa,
  • ağ istekleri gereksiz tekrar ediyorsa,
  • kullanıcı sayısı veya veri büyüdükçe sistem ağırlaşıyorsa.

Bu noktada çözüm genelde daha fazla teknoloji eklemek değil, mevcut yapıyı doğru kurmaktır.

Sonuç

React’te performansın büyük kısmı ileri seviye numaralardan değil, temel hataları yapmamaktan gelir.

En kritik beş hata şunlardır:

  1. Gereksiz yeniden render üretmek
  2. Fonksiyon ve nesneleri her render’da yeniden oluşturmak
  3. Büyük listeleri tek seferde ekrana basmak
  4. useEffect’i yanlış kullanmak
  5. State’i yanlış yerde tutmak

Bu hataları düzeltmek, çoğu projede ek kütüphane eklemekten daha fazla fayda sağlar. Çünkü sorun çoğu zaman React’in sınırında değil, kullanım biçimindedir.

İyi bir React geliştiricisi, sadece component yazan kişi değildir. Aynı zamanda neyin gereksiz yere tekrar çalıştığını gören, state’i doğru konumlandıran ve kullanıcı deneyimini düşürmeden yapıyı sade tutabilen kişidir.
