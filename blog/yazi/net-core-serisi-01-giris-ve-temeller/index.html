.NET Core Nedir?

.NET Core, Microsoft tarafından geliştirilen, açık kaynaklı, platformlar arası bir uygulama geliştirme altyapısıdır.
Windows, macOS ve Linux üzerinde çalışabilir.
Amaç aynı kod tabanıyla web, masaüstü, mobil ve bulut uygulamaları geliştirebilmektir.

.NET Framework’ün “Windows’a özel” yapısını aşmak için ortaya çıkmıştır. Bugün artık tek bir çatı altında .NET 8 gibi birleşik sürümlerle “tek .NET ekosistemi” haline gelmiştir.

.NET Framework ile .NET Core Arasındaki Farklar

| Özellik            | .NET Framework        | .NET Core / .NET                   |
| ------------------ | --------------------- | ---------------------------------- |
| Platform           | Sadece Windows        | Windows, macOS, Linux              |
| Açıklık            | Kapalı kaynak         | Açık kaynak                        |
| Performans         | Görece düşük          | Daha hızlı, hafif                  |
| Dağıtım            | Global Assembly Cache | Uygulamayla birlikte taşınabilir   |
| Modern API Desteği | Sınırlı               | Minimal API, Blazor, gRPC destekli |

Kısacası, .NET Core sadece “.NET’in yeni sürümü” değil, modern mimarinin yeniden tasarlanmış hâlidir.

SDK, Runtime, CLI Nedir? — Yapının Anatomisi

  1. SDK (Software Development Kit)
     → Geliştirme araçlarını içerir (dotnet build, dotnet run, dotnet new gibi).
     → Uygulama geliştirirken kullanılır.
  2. Runtime
     → Çalışan uygulamanın ihtiyaç duyduğu ortamdır.
     → Kullanıcıya dağıtılır, uygulamayı “çalıştıran” kısımdır.
  3. CLI (Command Line Interface)
     → dotnet komutlarını yazdığımız konsol aracıdır.
     → Örnek:
dotnet new webapi -n MyApp # Yeni Web API projesi oluşturur
dotnet run # Projeyi çalıştırır

Visual Studio ve CLI ile İlk .NET Core Projesi

Proje oluşturmanın iki temel yolu vardır:

1. Visual Studio (GUI)

  • “Yeni Proje” → “ASP.NET Core Web API” seç.
  • .NET 8 (veya geçerli sürüm) seçimini yap.
  • Projeyi oluştur, çalıştır.
  • Tarayıcıda https://localhost:5001/swagger sayfası otomatik açılır.

2. CLI (Terminal)

dotnet new webapi -n MyFirstApi
cd MyFirstApi
dotnet run

Bu komutlarla aynı sonucu alırsın. CLI yöntemini bilmek önemlidir çünkü otomasyon, CI/CD ve Docker gibi süreçlerde hep CLI kullanılır.

Program.cs ve Startup.cs Dosyalarının Rolü

.NET 5 öncesinde uygulamalar iki ana dosyayla başlardı:

  • Program.cs: Uygulamanın başlangıç noktası
  • Startup.cs: Servisleri ve middleware’leri yapılandırır

1. Klasik Yapı (Startup.cs olan sürümler)

// Program.cs
public class Program
{
    public static void Main(string[] args)
    {
        CreateHostBuilder(args).Build().Run(); // Uygulama burada başlatılır
    }

    public static IHostBuilder CreateHostBuilder(string[] args) =>
        Host.CreateDefaultBuilder(args)
            .ConfigureWebHostDefaults(webBuilder =>
            {
                webBuilder.UseStartup<Startup>(); // Startup sınıfını çağırır
            });
}
// Startup.cs
public class Startup
{
    // Bağımlılıkların (DI) tanımlandığı yer
    public void ConfigureServices(IServiceCollection services)
    {
        services.AddControllers(); // Controller’ları ekler
    }

    // Middleware (ara katman) pipeline’ı burada kurulur
    public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
    {
        if (env.IsDevelopment())
            app.UseDeveloperExceptionPage();

        app.UseRouting(); // URL yönlendirmelerini etkinleştirir
        app.UseAuthorization(); // Yetkilendirmeyi aktif eder
        app.UseEndpoints(endpoints => endpoints.MapControllers());
    }
}

Açıklama:

  • CreateHostBuilder uygulamayı başlatır.
  • ConfigureServices kısmı bağımlılıkları yönetir.
  • Configure kısmı HTTP isteğinin geçtiği pipeline’ı belirler.

2. .NET 6+ Minimal API Dönemi

.NET 6 ile birlikte Startup.cs kalktı, yapı sadeleştirildi:

// Program.cs (.NET 6+)
var builder = WebApplication.CreateBuilder(args);

// Servis ekleme
builder.Services.AddControllers();

var app = builder.Build();

// Middleware pipeline
app.UseRouting();
app.UseAuthorization();

app.MapControllers(); // Controller’ları endpoint olarak ekler

app.Run(); // Uygulamayı çalıştırır

Minimal API yapısında her şey Program.cs içinde toplanır.
Küçük projelerde kod okunabilirliğini artırır; büyük projelerde ise modüler hale getirilebilir.

Appsettings.json — Konfigürasyon Yönetimi

appsettings.json, uygulama ayarlarını merkezi olarak saklayan dosyadır.
 Veritabanı bağlantıları, log ayarları, e-posta servis bilgileri gibi yapılandırmalar burada tutulur.

Örnek:

{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "ConnectionStrings": {
    "DefaultConnection": "Server=.;Database=MyDb;Trusted_Connection=True;"
  }
}

Program.cs içinde kullanımı:

var builder = WebApplication.CreateBuilder(args);

// appsettings.json otomatik olarak okunur
var connectionString = builder.Configuration.GetConnectionString("DefaultConnection");
// Örnek: bu bağlantıyı EF Core’da kullanabiliriz
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(connectionString));
İpucu:
 appsettings.Development.json, appsettings.Production.json gibi environment bazlı yapılandırmalar da mümkündür.
 Bu sayede test ortamında farklı, üretimde farklı ayarlar kullanabilirsin.
