ORM Nedir?

ORM (Object-Relational Mapping), nesne tabanlı programlama ile ilişkisel veritabanları arasındaki farkı ortadan kaldıran bir tekniktir.
 Yani C# sınıflarını (örneğin User) SQL tablolarına dönüştürür, aradaki dönüşümü senin yerine yönetir.

Manuel SQL yazmak yerine şu şekilde kod yazarsın;

var users = context.Users.ToList();

ve EF Core bunu otomatik olarak şu sorguya çevirir:

SELECT * FROM Users;

ORM sayesinde:

  • Kod ile veritabanı senkron kalır,
  • Daha az hata olur,
  • Kod okunabilirliği artar.

Entity Framework Core’a Giriş

Entity Framework Core (EF Core), Microsoft’un .NET için geliştirdiği modern ORM aracıdır.
Avantajları:

  • Cross-platform (Windows, macOS, Linux)
  • LINQ desteğiyle güçlü sorgulama
  • Migration sistemiyle kolay tablo yönetimi
  • Asenkron işlemleri destekler (async/await)

EF Core Katman Entegrasyonu

Katmanlı mimaride EF Core genellikle DataAccess katmanında kullanılır.
Yani veritabanına erişen sınıflar burada yer alır.

Klasik yapı şu şekildedir:

MyApp
 ┣ Entities → Modeller
 ┣ DataAccess → DbContext ve Repository’ler
 ┣ Business → İş kuralları
 ┗ API → Sunum (Controller)

DbContext: Veritabanı ile Uygulama Arasındaki Köprü

DbContext, EF Core’un kalbidir.
 Tüm tablo (DbSet) erişimleri, sorgular, ve değişiklik takibi burada yapılır.

// DataAccess/Context/AppDbContext.cs
// Veritabanı bağlantısını yöneten DbContext sınıfı
public class AppDbContext : DbContext
{
    // Constructor: base'e options parametresi gönderilir (bağlantı ayarları burada taşınır)
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options)
    {
    }

    // Users tablosunu temsil eden DbSet
    public DbSet<User> Users { get; set; }

    // Opsiyonel: tablo isimleri veya ilişkiler burada yapılandırılabilir
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // User tablosunun zorunlu alanlarını belirtiyoruz
        modelBuilder.Entity<User>()
            .Property(u => u.Name)
            .IsRequired()
            .HasMaxLength(100);
    }
}

Not:

EF Core DbContext üzerinden tüm tablo işlemlerini izler.
Yeni bir kayıt eklendiğinde, değişiklikleri takip edip SaveChanges() çağrıldığında SQL komutlarına dönüştürür.

appsettings.json ve Bağlantı Ayarı

Bağlantı bilgileri appsettings.json dosyasında tutulur.
Bu sayede kod içinde bağlantı dizesi gömülü olmaz.

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=.;Database=MyAppDb;Trusted_Connection=True;"
  }
}
// Program.cs
// Veritabanı bağlantısının servis olarak eklenmesi
builder.Services.AddDbContext<AppDbContext>(options =>
{
    // Bağlantı dizesini konfigürasyondan okur
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection"));
});

Açıklama:

  • AddDbContext → EF Core’a AppDbContext’i tanıtır.
  • UseSqlServer → SQL Server kullanılacağını belirtir.
     (Alternatif: UseNpgsql PostgreSQL, UseSqlite SQLite vb.)

Migration (Veritabanı Güncellemeleri)

EF Core’da veritabanı tablolarını koddan oluşturmak için Migration sistemi kullanılır.

İlk Migration

dotnet ef migrations add InitialCreate

Bu komut, model sınıflarını analiz eder ve gerekli SQL scriptlerini üretir.

Veritabanını Oluşturmak

dotnet ef database update

Oluşturulan migration’ı uygular ve veritabanını oluşturur.

Migration dosyaları

Migrations/
 ┣ 20251017123000_InitialCreate.cs
 ┗ AppDbContextModelSnapshot.cs

Her migration dosyası, EF’in tabloları oluştururken kullandığı SQL komutlarını içerir.

Repository Örneği (EF Core Kullanarak)

// DataAccess/Repositories/UserRepository.cs
// EF Core üzerinden kullanıcı işlemlerini gerçekleştiren repository sınıfı
public class UserRepository : IUserRepository
{
    // DbContext nesnesi dependency injection ile alınır
    private readonly AppDbContext _context;

    public UserRepository(AppDbContext context)
    {
        _context = context;
    }

    // Tüm kullanıcıları getirir
    public async Task<List<User>> GetAllAsync()
    {
        // EF Core sorgusu: SELECT * FROM Users
        return await _context.Users.ToListAsync();
    }

    // Yeni kullanıcı ekler
    public async Task AddAsync(User user)
    {
        // Yeni kullanıcıyı bellekte ekler
        await _context.Users.AddAsync(user);

        // Değişiklikleri veritabanına kaydeder
        await _context.SaveChangesAsync();
    }

    // ID’ye göre kullanıcı getirir
    public async Task<User?> GetByIdAsync(int id)
    {
        // EF Core sorgusu: SELECT * FROM Users WHERE Id = {id}
        return await _context.Users.FindAsync(id);
    }

    // Kullanıcı siler
    public async Task DeleteAsync(User user)
    {
        // Nesneyi silmek üzere işaretler
        _context.Users.Remove(user);

        // Değişiklikleri kaydeder
        await _context.SaveChangesAsync();
    }
}

Asenkron Operasyonlar

EF Core’daki async / await kullanımı performansı artırır çünkü veritabanı sorguları genellikle IO-bound işlemlerdir.

Örnek:

// Controller seviyesinde asenkron kullanım
[HttpPost]
public async Task<IActionResult> AddUser(User user)
{
    // Servis katmanına kullanıcı eklemesi yapılır
    await _userService.AddAsync(user);

    // Başarılıysa 200 OK döner
    return Ok("Kullanıcı eklendi");
}

Özet: Asenkron sorgular CPU’yu bloke etmez, bu da web uygulamalarında ölçeklenebilirliği ciddi şekilde artırır.

LINQ ile Veri Sorgulama

EF Core, LINQ (Language Integrated Query) desteğiyle gelir.
Bu sayede SQL yazmadan sorgular oluşturabilirsin.

// Aktif kullanıcıları listeleme
var activeUsers = await _context.Users
    .Where(u => u.Email.Contains("@"))
    .OrderBy(u => u.Name)
    .ToListAsync();

EF Core bu sorguyu otomatik olarak SQL’e dönüştürür.
Performans açısından da oldukça optimize çalışır.

Katmanlı Mimari İçinde EF Core’un Yeri

EF Core yalnızca DataAccess katmanında olmalıdır.
Controller veya Service katmanları veritabanını doğrudan görmemelidir.

Örnek Akış (Kısaca)

  1. API → /api/users isteği gelir
  2. UserController → UserService çağırır
  3. UserService → UserRepository.GetAllAsync() çağırır
  4. UserRepository → EF Core üzerinden DbContext ile sorguyu yürütür
  5. Sonuç API’ye geri döner

Bu zincir, mimarideki katman bağımsızlığını korur.
