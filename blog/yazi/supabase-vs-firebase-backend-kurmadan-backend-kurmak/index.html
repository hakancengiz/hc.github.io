Supabase vs Firebase — Backend Kurmadan Backend Kurmak

software-development·16 Mart 2026·~5 dk okuma

Kısa versiyon: eğer Postgres, SQL ve tam kontrol istiyorsan Supabase; eğer tam entegre Google ekosistemi, güçlü SDK’lar ve otomatik ölçeklenebilir NoSQL istiyorsan Firebase daha hızlı yol aldırır. Aşağıda karar vermeyi kolaylaştıracak teknik farklar, kullanım örnekleri ve pratik tavsiyeler var.

1) Temel mimari fark — ne alırsın?

  • Supabase: Her proje için tam bir Postgres veritabanı (SQL), Row-Level Security (RLS), instant REST/Realtime API, Storage ve Edge Functions sunar. Yani verinin modelleme/ilişki (joins, SQL) tarafında tam kontrolün olur.
  • Firebase: Genelde iki ana gerçek zamanlı DB sunar: Realtime Database (JSON ağaç) ve Cloud Firestore (document-based NoSQL). SDK’lar (Web/Android/iOS/Flutter) zengin, Google Cloud servisleriyle sıkı entegrasyon var.

Ne anlama geliyor?

  • İlişkisel veri, kompleks sorgular, ACID garantileri ve SQL çıktısı istiyorsan Supabase hızlıca “backend kurmuş” hissi verir.
  • Hızlı realtime sync, mobil-first offline sync ve Google Cloud ekosistemiyle doğrudan entegrasyon gerekliyse Firebase avantajlı.

2) Authentication & Authorization

  • Supabase: Email/password, OAuth sağlayıcıları, magic links ve Postgres RLS ile veritabanı seviyesinde veri erişim politikaları yazmana izin verir. RLS ile “kullanıcı sadece kendi satırını görsün” gibi kuralları DB düzeyinde enforce edebilirsin.
  • Firebase: Çok güçlü hazır auth sağlayıcıları (email, phone auth, Google/Facebook/SAML vb.) ve client SDK’ları ile entegre çalışır. Firestore/Realtime DB için security rules ile erişim kontrolü sağlanır.

Pratik tavsiye: Eğer güvenlik kurallarını DB’de (SQL mantığıyla) ifade etmek istersen Supabase RLS güçlü bir silah. Eğer telefonla doğrulama, federated login vs. hızlı bir şekilde entegre etmek istiyorsan Firebase işini çabuk görür.

3) Gerçek zamanlı (realtime) ve offline davranış

  • Realtime: Her iki platform da realtime özellik sunar. Supabase, Postgres tabanlı değişiklikleri realtime olarak yayar; Firebase ise klasik olarak Realtime DB / Firestore ile client SDK’larda realtime ve offline sync sağlar.
  • Offline: Firebase (özellikle Firestore) mobil/JS SDK’larında offline-first senaryoları native destekler; Supabase tarafında offline senkronizasyon için ek katman/çözüm gerekebilir.

Ne seçmeli? Offline-first mobil uygulama hedefliyorsan Firebase daha az sürpriz çıkarır.

4) Sorgulama gücü ve limitler

  • Supabase = SQL: JOIN, window functions, full-text search (Postgres eklentileri) gibi güçlü sorgular. Karmaşık raporlama/analiz gerekiyorsa SQL işini yapar.
  • Firebase = NoSQL: Firestore sorguları güçlü ama ilişkisel sorgulardan farklı; JOIN yok, bazı sorgular “denormalize etme” ile çözülür.

Kural: Veriyi ilişkisel düşünüyorsan Supabase, belgeler/denormalize/özet veri uygunsa Firebase.

5) SDK’lar, geliştirme hızı ve geliştirici deneyimi

  • Firebase: Çok iyi dökümantasyon ve ilk parti SDK’lar (Web, Android, iOS, Flutter). Authentication, Cloud Functions, Hosting ve Analytics gibi entegre servisler hızlı prototipleme sağlar.
  • Supabase: supabase-js gibi resmi SDK’lar, instant REST & realtime ile hızlı başlanabilir; SQL ve DB yönetimi için dashboard güçlüdür. Postgres bilgisi varsa prodabilete geçiş daha kontrollü olur.

6) Fiyatlandırma ve ölçeklenebilirlik

  • Supabase: Free katman ile başlayıp pro planlara geçiş var; disk/egress/invocation gibi metriklere göre ücretlendirme. Büyük veriler ve egress maliyeti önemli.
  • Firebase: Spark (free) ve Blaze (pay-as-you-go) gibi planlar; birçok servis Google Cloud altyapısına dayandığı için faturalama bir hayli granular olur. Okuma/yazma/dep storage/egress bazlı ücretler dikkat ister.

Pratik: Her iki platformda da “ücretsizken problemsiz, production’dayken fatura sürprizleri” riski var — özellikle yoğun okuma/yazma/egress senaryolarında. Erken aşamada kullanım profiline göre kaba maliyet hesaplayıp test et.

7) Migration & vendor-lock

  • Supabase: Postgres olduğu için taşınma (self-hosted veya başka Postgres) daha kolay; SQL dump/pg_restore ile migration nispeten standart.
  • Firebase: NoSQL yapısı (Firestore, RealtimeDB) başka platforma taşınırken veri modeli yeniden düşünülmeli — migration maliyeti daha yüksek olabilir.

Kural: Eğer vendor-lock riskini minimize etmek istiyorsan ve veri taşınabilirliği önemliyse Supabase avantajlıdır.

8) Kod örnekleri — hızlı karşılaştırma (JS/TS)

Supabase: kayıtlı kullanıcıyla not ekleme (JS)

// supabase-client.js
import { createClient } from "@supabase/supabase-js";

const supabase = createClient("https://your.supabase.url", "public-anon-key");

// Not ekleme fonksiyonu
export async function addNote(content) {
  // notes tablosuna insert atıyoruz (Postgres)
  const { data, error } = await supabase
    .from("notes")            // hedef tablo
    .insert([{ content }])    // eklenmek istenen satır
    .select();                // eklenen kaydı geri al

  if (error) throw error;
  return data[0];            // eklenen kayıt
}

Açıklama: Supabase .from("table") ile Postgres tablolarına SQL benzeri işlemler yapar; sonuç SQL tabanlıdır.

Firebase (Firestore): aynı senaryo (modular SDK v9+)

// firebase-client.js
import { initializeApp } from "firebase/app";
import { getFirestore, collection, addDoc, serverTimestamp } from "firebase/firestore";

const app = initializeApp({
  apiKey: "...", authDomain: "...", projectId: "your-project"
});
const db = getFirestore(app);

// Not ekleme fonksiyonu
export async function addNote(content) {
  // Firestore collection'ına document ekliyoruz
  const docRef = await addDoc(collection(db, "notes"), {
    content,
    createdAt: serverTimestamp()
  });

  return { id: docRef.id };
}

Açıklama: Firestore’da veriler collection/document şeklinde saklanır; SQL JOIN yok, sorgu modeline göre denormalize gerekir.

9) Hızlı seçim rehberi — hangi duruma hangi platform?

  • Hızlı MVP, mobil offline sync, tight Google ekosistemi (Analytics/FCM) → Firebase.
  • Complex queries, relational data, SQL expertise, taşınabilirlik → Supabase.
  • Realtime + SQL garanti isteniyorsa → Supabase (Postgres değişiklik yayınlama).

10) Gerçek dünya uyarıları (yapılmaması gerekenler)

  • Firebase/Firestore kullanıp ilişkisel veri modelini NoSQL gibi zorlamak → sorgu/kopyalama patlaması.
  • Supabase’de dashboard’da her şeyi client-side’a doğrudan bırakmak (RLS konfigurasyonu yapılmadan) → güvenlik riski.
  • Fiyat testlerini atlamadan prod’a geçmek — okuma/yazma/egress kalemleri hızla fatura oluşturabilir.

11) Örnek proje fikri — 30 dakikada canlı prototip (adımlar)

  • Supabase/Firebase hesabı aç (ücretsiz plan).
  • Basit notes tablosu/collection oluştur.
  • Frontend: Vite + React + Supabase/Firebase SDK — temel CRUD UI.
  • Auth ekle: email/login (hazır provider).
  • Deploy: Vercel/Netlify.
  • İzleme: gerçek read/write metriklerini 24–48 saat test et, maliyet profilini çıkar.

Sonuç — senin için kısa takeaways

  • Supabase: SQL, RLS, taşınabilirlik, güçlü sorgular; backend kurmadan backend isteyenler için ideal.
  • Firebase: Entegre SDK’lar, offline-first mobil deneyimi, Google hizmetleriyle seamless entegrasyon; hızlı prototipleme ve mobil uygulamalar için güçlü.
