ASP.NET Core’da JWT (JSON Web Token) ile Güvenli API Geliştirme

Kimlik Doğrulama (Authentication) Nedir?

Authentication, bir kullanıcının kim olduğunu doğrulama işlemidir.
 Örneğin, “bu isteği gönderen gerçekten admin mi?” sorusuna cevap verir.

Authorization (Yetkilendirme) ise, Kullanıcının ne yapabileceğini belirler. Örneğin, bir moderatör kullanıcıları görebilir ama silemez.

Bu ikisi genellikle birlikte çalışır:

Authentication = Kimsin?
Authorization = Ne yapabilirsin?

JWT (JSON Web Token) Nedir?

JWT, kimlik doğrulama bilgisini güvenli bir şekilde taşıyan bir formattır.
Kullanıcı giriş yaptığında sunucu bir token (jeton) üretir ve bu token her istekte gönderilir.

JWT üç parçadan oluşur:

Header.Payload.Signature
Örnek:
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJVc2VySWQiOjEsIk5hbWUiOiJIYWthbiJ9.qTqkZgE6…

Bu token çözülürse şuna benzer bir JSON elde edilir:

{
  "UserId": 1,
  "Name": "Hakan",
  "exp": 1734359090
}

Adım 1: Kullanıcı Modeli ve DTO

// Entities/User.cs
// Sistemdeki kullanıcıyı temsil eden model
public class User
{
    // Benzersiz kimlik numarası
    public int Id { get; set; }

    // Girişte kullanılacak kullanıcı adı
    public string Username { get; set; } = string.Empty;

    // Parola (hashlenmiş şekilde saklanır)
    public string PasswordHash { get; set; } = string.Empty;

    // Kullanıcının sistemdeki rolü (örnek: "Admin", "User")
    public string Role { get; set; } = "User";
}

DTO (veri transfer modeli) giriş için:

// Entities/DTOs/LoginRequestDto.cs
public class LoginRequestDto
{
    [Required]
    public string Username { get; set; } = string.Empty;

    [Required]
    public string Password { get; set; } = string.Empty;
}

Adım 2: Token Servisi

Token üretimi için özel bir servis tanımlarız.

// Business/Services/TokenService.cs
// Kullanıcı girişinde JWT üreten servis sınıfı
public class TokenService
{
    private readonly IConfiguration _configuration;

    // Konfigürasyondan gizli anahtar alınır
    public TokenService(IConfiguration configuration)
    {
        _configuration = configuration;
    }

    // Giriş yapan kullanıcı için token üretir
    public string GenerateToken(User user)
    {
        // 1️⃣ Token’a eklenecek kullanıcı bilgileri (claim)
        var claims = new[]
        {
            new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
            new Claim(ClaimTypes.Name, user.Username),
            new Claim(ClaimTypes.Role, user.Role)
        };

        // 2️⃣ Gizli anahtar (appsettings.json’dan okunur)
        var key = new SymmetricSecurityKey(
            Encoding.UTF8.GetBytes(_configuration["Jwt:Key"])
        );

        // 3️⃣ Token’ın imzalanması için güvenlik kimliği
        var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

        // 4️⃣ Token nesnesinin oluşturulması
        var token = new JwtSecurityToken(
            issuer: _configuration["Jwt:Issuer"],
            audience: _configuration["Jwt:Audience"],
            claims: claims,
            expires: DateTime.Now.AddHours(2), // 2 saat geçerli
            signingCredentials: creds
        );

        // 5️⃣ Token string’e dönüştürülür ve döndürülür
        return new JwtSecurityTokenHandler().WriteToken(token);
    }
}

Adım 3: appsettings.json Ayarları

JWT anahtar bilgilerini burada saklarız:

{
  "Jwt": {
    "Key": "BuCokGizliBirAnahtardir123!",
    "Issuer": "MyAppAPI",
    "Audience": "MyAppClient"
  }
}

Bu anahtar çok önemlidir.
Üretim ortamında environment değişkenlerinde saklanmalıdır, dosyada açık bırakılmaz.

Adım 4: Authentication Yapılandırması

// Program.cs
// JWT yapılandırmasını .NET Core servisine ekler
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        // Token doğrulama parametreleri
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true, // Token kimden geldi kontrolü
            ValidateAudience = true, // Token kime ait kontrolü
            ValidateLifetime = true, // Token süresi dolmuş mu
            ValidateIssuerSigningKey = true, // İmza geçerli mi
            ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidAudience = builder.Configuration["Jwt:Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Key"])
            )
        };
    });
// Middleware sırası (çok önemli!)
app.UseAuthentication(); // Kullanıcıyı doğrular
app.UseAuthorization();  // Rol kontrolü yapar
app.MapControllers();

Adım 5: Login Endpoint

// API/Controllers/AuthController.cs
// Giriş yapan kullanıcıya token dönen controller
[ApiController]
[Route("api/[controller]")]
public class AuthController : ControllerBase
{
    private readonly IUserService _userService;
    private readonly TokenService _tokenService;

    public AuthController(IUserService userService, TokenService tokenService)
    {
        _userService = userService;
        _tokenService = tokenService;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login(LoginRequestDto login)
    {
        // Kullanıcı var mı kontrol edilir
        var user = await _userService.ValidateUserAsync(login.Username, login.Password);
        if (user == null)
            return Unauthorized("Geçersiz kullanıcı adı veya parola");

        // Kullanıcı doğrulandı, token oluşturulur
        var token = _tokenService.GenerateToken(user);

        // Token JSON olarak döndürülür
        return Ok(new { token });
    }
}

Adım 6: Yetkilendirme (Authorization)

Artık belirli endpoint’lere erişimi sınırlandırabiliriz:

// API/Controllers/UserController.cs
[Authorize] // Tüm endpoint’ler login gerektirir
[ApiController]
[Route("api/[controller]")]
public class UserController : ControllerBase
{
    [HttpGet]
    public IActionResult GetProfile()
    {
        // Kullanıcının JWT içindeki Name bilgisini alır
        var username = User.Identity?.Name;
        return Ok($"Merhaba {username}, profil sayfasındasın!");
    }

    // Sadece Admin rolündekiler bu endpoint’e erişebilir
    [Authorize(Roles = "Admin")]
    [HttpDelete("{id}")]
    public IActionResult DeleteUser(int id)
    {
        return Ok($"Kullanıcı {id} silindi.");
    }
}

JWT Akışı (Özet)

1️⃣ Kullanıcı /api/auth/login isteği gönderir
2️⃣ Sunucu kimlik bilgilerini doğrular
3️⃣ Geçerliyse JWT token üretir
4️⃣ Kullanıcı her istekte Authorization: Bearer <token> başlığıyla token’ı gönderir
5️⃣ Sunucu token’ı doğrular, kullanıcı kimliğini tanır

Test İçin Örnek

İstek (Login):

POST /api/auth/login
Content-Type: application/json

{
  "username": "hakan",
  "password": "1234"
}

Yanıt:

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6Ikp..."
}

Korunan bir endpoint’e erişim:

GET /api/user
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Ek Güvenlik Önerileri

Token sürelerini kısa tut (1–2 saat)
Refresh token mekanizması ekle
HTTPS zorunlu yap
Parolaları SHA256 veya bcrypt ile hashle
appsettings.json içindeki anahtarı ortam değişkenine taşı

Esktra: Claim Nedir?

Claim, bir kullanıcının kimliğine ait özellik veya iddia bilgisidir.
Yani token içinde taşınan “hakkında” veriler diyebiliriz.

Örneğin bir JWT token’ın içeriği şuna benzer:

{
  "sub": "1",
  "name": "Hakan",
  "role": "Admin",
  "email": "hakan@example.com",
  "exp": 1734383000
}

Buradaki her anahtar (sub, name, role, email) bir claim’dir.

Yani:

  • sub → user ID
  • name → kullanıcı adı
  • role → sistemdeki rol
  • email → iletişim bilgisi
  • exp → token geçerlilik süresi

Claim’lerin Amacı

Claim’ler, kimlik doğrulama sonrasında kullanıcıya ait bilgileri taşıyarak:

  • Authorization (yetki kontrolü) yapılmasını sağlar,
  • Kullanıcı bilgisinin her istekte veritabanından çekilmesini engeller,
  • Token üzerinden kimlik doğrulamasını stateless hale getirir.

Yani token doğrulandığında .NET Core otomatik olarak bu claim’leri çözer
 ve User nesnesine aktarır;

// Controller içinde JWT’den claim bilgisi okuma
[Authorize]
[HttpGet("profile")]
public IActionResult GetProfile()
{
    // Kullanıcının JWT içindeki Name ve Role bilgilerini alıyoruz
    var username = User.FindFirst(ClaimTypes.Name)?.Value;
    var role = User.FindFirst(ClaimTypes.Role)?.Value;

    return Ok($"Kullanıcı: {username}, Rol: {role}");
}

Özetle:

  • Claim, token içindeki kullanıcı özelliklerini taşır.
  • [Authorize(Roles = "Admin")] gibi yapılar ClaimTypes.Role üzerinden çalışır.
  • Token doğrulandığında .NET, claim’leri User objesine otomatik işler.
  • Sensitive veriler (örneğin parola) claim’e konulmamalıdır.
