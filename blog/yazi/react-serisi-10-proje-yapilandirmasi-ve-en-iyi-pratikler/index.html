Büyük ve profesyonel React projelerinde, düzensiz dosya yapısı ve karmaşık importlar zamanla sorun yaratır.
Bu bölümde, temiz mimari, alias kullanımı, environment değişkenleri ve deployment konularını inceleyeceğiz.

1. Temiz Proje Yapısı (Folder Structure)

Tipik bir React projesi yapısı şöyle olabilir:

src/
│
├─ components/      # Tekrar kullanılabilir UI bileşenleri
│   ├─ Button.jsx
│   └─ Card.jsx
│
├─ pages/           # Sayfa component’leri
│   ├─ Home.jsx
│   └─ About.jsx
│
├─ hooks/           # Custom hook’lar
│   └─ useFetch.js
│
├─ context/         # Context API veya global state
│   └─ AuthContext.jsx
│
├─ services/        # API çağrıları veya servisler
│   └─ api.js
│
├─ utils/           # Yardımcı fonksiyonlar
│   └─ formatDate.js
│
├─ assets/          # Görseller, ikonlar, stil dosyaları
│   ├─ images/
│   └─ styles/
│
├─ App.jsx
└─ main.jsx
  • Component ve sayfaları ayrı tutmak, büyük projelerde okunabilirliği artırır.
  • hooks, context, services ve utils klasörleri iş mantığını modüler hale getirir.

2. Absolute Import / Alias Kullanımı

Projeler büyüdükçe ../../../components/Button gibi importlar karmaşa yaratır.
Vite veya Create React App’de alias kullanmak çözüm sağlar.

Vite Örneği:

// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import path from "path";

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      "@components": path.resolve(__dirname, "./src/components"),
      "@pages": path.resolve(__dirname, "./src/pages"),
      "@hooks": path.resolve(__dirname, "./src/hooks"),
    },
  },
});

Artık importlar şöyle kullanılabilir:

import Button from "@components/Button";
import Home from "@pages/Home";
Daha okunabilir ve taşınabilir import’lar elde edilir.

3. Environment Değişkenleri

Projelerde farklı ortamlar (development, production) için environment değişkenleri kullanılır.

  • .env (development)
  • .env.production (production)

Örnek .env:

VITE_API_URL=https://api.devsite.com

Kullanımı:

const apiUrl = import.meta.env.VITE_API_URL;

fetch(`${apiUrl}/users`)
  .then((res) => res.json())
  .then((data) => console.log(data));
VITE_ prefix’i, Vite projelerinde env değişkenlerini erişilebilir kılar.

4. Clean Architecture / Best Practices

  • Component’ler küçük ve tek iş yapacak şekilde olmalı
  • State yönetimi global mi local mi belirlenmeli
  • Side-effect’ler hook’lar veya services içinde olmalı
  • Reusable component’ler ayrı klasörde toplanmalı
  • Tests component ile birlikte veya __tests__ klasöründe bulunmalı

5. Deployment

React uygulamalarını hızlıca deploy etmek için popüler platformlar:

Vercel

npm run build
# Build sonrası Vercel CLI ile deploy
vercel

Netlify

  • Build: npm run build
  • dist veya build klasörünü Netlify’e yükle

GitHub Pages

npm run build
npm install gh-pages --save-dev

package.json ayarları:

"homepage": "https://username.github.io/repo-name",
"scripts": {
  "predeploy": "npm run build",
  "deploy": "gh-pages -d build"
}
npm run deploy

Özet

| **Environment Variables**   | Farklı ortamlar için API URL ve ayarları yönetir                         |
| **Clean Architecture**      | Kodun okunabilir, modüler ve test edilebilir olmasını sağlar             |
| **Deployment**              | Vercel, Netlify, GitHub Pages gibi platformlarda canlıya almayı sağlar   |
