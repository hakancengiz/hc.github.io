DNS Nedir? Bir Siteye Erişmek İstendiğinde Arka Planda Ne Olur?

web·9 Mayıs 2026·~3 dk okuma

Tarayıcıya bir site yazarsın:

www.google.com

Enter’a basarsın ve sayfa açılır. Basit gibi görünür ama aslında o küçük hareketin arkasında birden fazla sistem katmanı çalışır.

İşte bu sürecin adı:
DNS çözümleme süreci + HTTP isteği yolculuğu

DNS Nedir?

DNS, İngilizce açılımıyla Domain Name System demektir.

Türkçesiyle:
 Alan adı sistemi

DNS’in görevi şudur:

İnsanların yazdığı site adını (örneğin google.com), bilgisayarların anlayacağı IP adresine çevirmek.

Çünkü bilgisayarlar “google.com” anlamaz.

Onlar şunu anlar:

142.250.185.78

Yani DNS aslında internetin telefon rehberidir.

Sen isim yazarsın, o sana numara verir.

Peki neden IP yazmıyoruz?

Çünkü IP adresleri:

  • Hatırlaması zor
  • Sürekli değişebilir
  • İnsanlar için okunabilir değildir

DNS bu problemi çözer.

Bir siteye girince gerçekte ne olur?

Şimdi olayı adım adım inceleyelim.

1. Tarayıcı cache kontrolü

Tarayıcı önce kendi hafızasına bakar.

“Bu domainin IP’sini daha önce öğrendim mi?”

Eğer biliyorsa direkt kullanır.

Bu aşamaya browser cache denir.

2. İşletim sistemi cache’i

Tarayıcı bilmiyorsa işletim sistemi devreye girer.

Windows veya macOS kendi DNS cache’ine bakar.

Burada daha önce çözülmüş domainler tutulur.

3. Router / modem cache

Eğer orada da yoksa, router kontrol edilir.

Evdeki modem bile DNS bilgisi tutabilir.

4. DNS sunucusuna istek gider

Hiçbir yerde bulunamazsa asıl süreç başlar.

Bilgisayar bir DNS server’a sorar:

“www.google.com’un IP adresi nedir?”

Genelde kullanılan DNS server’lar:

  • Google DNS (8.8.8.8)
  • Cloudflare (1.1.1.1)
  • ISP DNS (internet sağlayıcın)

5. DNS çözümleme zinciri

DNS server direkt cevap vermeyebilir.

O zaman şu zincir çalışır:

  • Root DNS (kök sunucu)
  • TLD DNS (.com, .net gibi)
  • Authoritative DNS (asıl kayıt)

Burada kritik nokta şu:

DNS tek bir yer değildir, dağıtık bir sistemdir.

6. IP adresi döner

Sonunda DNS sana IP adresini verir.

Örnek:

www.google.com → 142.250.185.78

7. HTTP isteği başlar

Artık tarayıcı gerçek sunucuya gider.

Bu noktada DNS işi biter.

Sonrası:

  • TCP bağlantısı kurulur
  • HTTP/HTTPS isteği gönderilir
  • Sunucu cevap verir
  • Sayfa yüklenir

Sen bir site yazdığında:

  • DNS çözülür
  • Birden fazla cache katmanı kontrol edilir
  • Dünya üzerindeki DNS sunucuları devreye girer
  • Sonra gerçek sunucuya bağlanılır

Ama tüm bunlar: milisaniyeler içinde olur.

DNS neden önemlidir?

Çünkü:

  • Site taşınabilir (IP değişebilir)
  • Trafik yönlendirilebilir
  • CDN sistemleri çalışır
  • Yük dengeleme yapılabilir

DNS aslında internetin “yönlendirme beyni” gibidir.

Basit C# ile DNS çözümleme örneği

Aşağıda bir domainin IP’sini nasıl çözdüğünü görebilirsin.

using System; // Temel sistem fonksiyonlarını kullanmak için eklenir
using System.Net; // DNS çözümleme işlemleri için eklenir

class Program // Ana program sınıfı
{
    static void Main() // Uygulama başlangıç noktası
    {
        string domain = "google.com"; // Çözümlenecek domain tanımlanır

        IPHostEntry hostEntry = Dns.GetHostEntry(domain); // Domain IP'ye çevrilir

        foreach (IPAddress ip in hostEntry.AddressList) // Tüm IP adresleri döngüye alınır
        {
            Console.WriteLine(ip.ToString()); // IP adresi ekrana yazdırılır
        }
    }
}

Burada olan şey şudur:

  • Dns.GetHostEntry → DNS server’a istek atar
  • Domain’i IP listesine çevirir
  • Birden fazla IP dönebilir (load balancing nedeniyle)

DNS cache neden önemli?

DNS her seferinde sorgulansa internet çok yavaşlardı.

Bu yüzden:

  • Tarayıcı cache tutar
  • OS cache tutar
  • DNS server cache tutar

Bu yapı performansın temel sebeplerinden biridir.

DNS problemleri neden kritik olur?

DNS bozulursa:

  • Site çalışıyor olsa bile açılmaz
  • IP doğru olsa bile erişim olmaz
  • “Internet var ama siteler açılmıyor” durumu oluşur

Yani DNS, görünmeyen ama kritik bir katmandır.

Sonuç

Bir siteye yazıp Enter’a bastığında:

  1. DNS çözümleme başlar
  2. Cache katmanları kontrol edilir
  3. DNS server IP döner
  4. TCP bağlantısı kurulur
  5. HTTP isteği gider
  6. Sayfa yüklenir

Ama kullanıcı sadece şunu görür:

“Site açıldı”

Sen bir isim yazarsın, dünya üzerindeki dağıtık bir sistem saniyeler içinde seni doğru sunucuya yönlendirir.
